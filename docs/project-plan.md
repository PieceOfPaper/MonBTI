# MonBTI 프로젝트 기획

- 상태: 초기 기획
- 최신 방향 반영일: 2026-10-08

## 소개

몬스터헌터 입문자가 질문에 답하면서 자신의 플레이 취향에 맞는 무기를 찾도록 돕는 웹 검사입니다.
MBTI 검사처럼 진행하되, 몬헌의 무기 선택에 맞는 분류와 추천 방식을 설계합니다.
기존 유저에게는 결과를 보고 재미있게 즐기는 콘텐츠를 제공합니다.

## 확정된 대상과 목적

| 대상 | 목적 | 기획 기준 |
| --- | --- | --- |
| 입문자 — 주 대상 | 무기 선택에 도움 | 사전 게임 지식 없이 질문과 추천 이유를 이해할 수 있어야 함 |
| 기존 유저 | 재미 | 취향을 돌아보며 결과를 즐길 수 있어야 함 |

## 작품 선택

- 가장 첫 페이지에서 기준 작품을 선택합니다.
- 현재 지원하고 선택할 수 있는 작품은 몬스터헌터 와일즈뿐입니다.
- 와일즈를 선택하면 와일즈용 검사로 진입합니다.
- 다른 작품의 추가 여부와 시점은 미정입니다.
- 현재 한 작품만 지원해도 작품 선택 화면은 유지합니다.
- 다른 작품의 준비 중 항목을 표시할지는 미정입니다.

## 확정된 기본 흐름

1. 기준 작품 선택
2. 해당 작품의 질문에 답변
3. 성향 및 무기 추천 결과 확인

모든 사용자는 같은 질문을 `question_order` 순서로 받으며, 답변에 따른 질문 분기는 사용하지 않습니다.
응답은 1~6단계 동의 척도이며 중립 선택지는 없습니다.
한 질문이 여러 축에 영향을 줄 수 있습니다. 각 축의 부호 있는 가중치에 응답 계수를 곱하고 축별 기여도를 합산합니다.
결과 화면은 1~3순위 무기, 기준 비교 방사형 차트, 무기 소개 영상, 이미지·링크 공유로 구성합니다. 순위는 확정한 추천 공식으로 계산합니다. 상세 계산과 동작은 [검사 설계](test-design.md)를 따릅니다.

## 질문 작성 방향

몬헌 지식 없이 답할 수 있는 일상적인 상황·포괄적인 행동 선호를 간접적으로 묻습니다.
소재는 살짝 비틀 수 있지만 문장은 바로 이해할 수 있어야 합니다.
하나의 응답을 여러 축으로 해석할 수 있으며, 서로 다른 답을 하고 싶은 독립된 주장들을 한 질문에 묶지 않습니다.
앞으로 문항 작성·수정·검토는 [질문 작성 가이드](question-guide.md)를 따릅니다.
가이드의 예시와 축 연결은 설명·검토용이며 실제 문항·가중치의 확정이 아닙니다.

## 무기 선택 기준

멋짐 등 주관적인 인상보다 입문자의 손에 익숙해질 수 있는 플레이 특성을 기준으로 삼습니다.

| 기준 | 영문명·필드 이름 | 의미 |
| --- | --- | --- |
| 대미지 집중도 | attack | 자주 대미지를 누적하는 지속형 ↔ 준비한 기회에 큰 대미지를 집중하는 한방형 |
| 자유도 | freedom | 행동을 시작한 뒤 마음을 바꿨을 때 공격·이동·방향·회피·가드 등 원하는 다음 행동으로 빠르게 전환할 수 있는 정도 |
| 운용 복잡도 | complexity | 상황에 맞는 행동·파생·상태 전환을 골라야 제 역할을 하는 정도 |
| 관리 부담 | management | 전투 중 무기 고유 자원·게이지·강화 상태·지속 시간 등을 꾸준히 확인하고 유지·소비·보충해야 하는 정도 |
| 카운터 취향 | counter | 몬스터의 행동을 기다렸다 정확한 때에 받아치는 플레이가 얼마나 중심인가 |

`attack`은 내부 필드명이며 사용자 화면에는 **한방**으로 표시합니다. 공격 속도가 아니라 대미지 보상의 분배 방식입니다. 운용 복잡도는 연속된 과정이나 기술 수가 아니라 제 역할을 위해 올바른 행동·파생·상태 전환을 선택해야 하는 정도이며, 관리 부담은 수집·축적 성향이나 일반적인 정리 습관을 평가하지 않습니다.
대미지 집중도와 카운터 취향은 사용자의 선호와 무기 특성이 얼마나 가까운지를 보고, 자유도·운용 복잡도·관리 부담은 무기의 행동 특성과 요구 수준을 평가합니다.
자유도는 입문자가 행동 중 판단을 바꿨을 때 실제 캐릭터가 원하는 다음 행동으로 전환되는 체감을 평가합니다. 위기 전환성 35%, 공격 즉응성 25%, 방향·위치 수정 25%, 행동 단위 15%를 사용하며, 세부 판정과 현재 무기별 초기값은 [검사 설계](test-design.md)를 따릅니다.
`counter`의 사용자 점수는 부담 수용량보다 카운터 플레이를 좋아하는 정도에 가깝습니다. 무기 점수는 기술 보유 여부가 아니라 실제 운용에서 카운터가 차지하는 중심도이며, 추천에서는 두 값의 차이를 대칭적으로 비교합니다. 낮은 사용자 점수는 카운터에 대한 혐오가 아니라 먼저 주도하거나 카운터가 필수가 아닌 방식을 더 선호한다는 뜻입니다.
세부 평가 범위는 [검사 설계](test-design.md)에 기록합니다.

## 추천 계산

- 질문 응답의 축별 가중 합계를 그 축의 가중치 절댓값 합으로 나누어 사용자 점수를 0~100으로 정규화합니다. 50은 어느 쪽으로도 기울지 않은 상태입니다.
- `attack`과 `counter`는 사용자 점수와 무기 값의 절대 차이가 작을수록 적합합니다.
- `freedom`은 사용자가 원하는 자유도보다 무기의 자유도가 부족한 만큼만 벌점을 줍니다. 더 자유로운 무기는 벌점이 없습니다.
- `complexity`와 `management`는 무기의 요구량이 사용자의 수용 점수를 넘는 만큼만 벌점을 줍니다. 사용자가 감당할 수 있는 수준보다 단순한 무기는 벌점이 없습니다.
- 각 축의 적합도는 `100 - 불일치`이며, 초기 버전은 다섯 축을 같은 비중으로 평균하여 무기별 최종 점수를 만듭니다. 점수가 높은 순서로 1~3순위를 추천합니다.
- 최종 점수가 같으면 가장 큰 단일 축 불일치가 작은 무기를 우선하고, 그래도 같으면 시트의 무기 순서를 사용합니다. 계산 중에는 반올림하지 않습니다.

## 데이터 관리

- 무기와 질문 데이터의 원본은 [MonBTI_테이블](https://docs.google.com/spreadsheets/d/124oQusXZQ6_F9-UYUVAzG3TD7u50oBjKdBIEbrT7Ras/edit)입니다.
- 와일즈용 무기는 `Wilds_Weapon`, 질문은 `Wilds_Question`에서 편집합니다. 여섯 응답 문구·환산식은 사이트의 공통 정의로 관리합니다.
- 무기 기준값은 0~100의 연속값으로 입력하며 25점 단위로 제한하지 않습니다. 질문은 질문당 한 행으로 작성하고 다섯 축에 -100~100 가중치를 입력합니다. `axis`·`reverse`는 사용하지 않습니다.
- 응답 1~6의 계수는 -1·-0.6·-0.2·0.2·0.6·1입니다. 음수 가중치는 방향을 반대로 바꾸며, 0·빈칸은 해당 축에 영향이 없습니다. 미측정 축은 null로 유지합니다.
- 무기 14개의 축 값과 질문 문항·가중치는 원본 시트에서 계속 조정합니다. 별도의 임시 데이터 구분 없이 값을 직접 수정해 사용합니다. 세 번째 축은 기획상 `complexity`로 확정했으며, 현재 시트·JSON·코드의 `combo` 필드 마이그레이션은 별도 구현 작업으로 진행합니다.
- GitHub Pages는 시트에서 내보낸 데이터를 검증·변환한 JSON을 배포에 포함하도록 개발합니다.
- 원본 변경은 내보내기·변환·저장소 반영·배포를 거쳐 사이트에 적용합니다. Actions의 **시트 데이터 갱신 → Run workflow**를 `main`에서 실행하면 이 과정을 자동으로 수행합니다.
- 자동 갱신은 무기·질문 JSON 두 파일만 커밋합니다. 데이터가 같으면 시각 메타데이터와 기존 파일을 유지하며, 시트 다운로드·검증·테스트·빌드 오류가 있으면 커밋하지 않습니다.
- 열 정의와 변환 규칙은 [시트 데이터 설계](data-schema.md)를 따릅니다. 변환기(`npm run data:convert`)와 사이트의 JSON 로딩을 구현했습니다.

## 개발 및 운영

- GitHub Pages에 배포할 웹사이트를 만듭니다.
- Vite 기반 정적 웹사이트로 개발하고 Vitest로 단위 테스트를 실행합니다.
- `main` 브랜치 푸시는 GitHub Actions를 통해 검증 및 Pages 배포로 이어집니다.
- Codex와 Claude Code로 개발합니다.
- 기획서는 docs/ 하위 Markdown으로 관리합니다.
- 대화에서 정리한 내용은 사용자가 저장소 반영을 명시적으로 요청했을 때만 기록합니다.
- 반영을 요청받은 방향 변경은 README와 관련 기획에 함께 갱신합니다.

## 현재 미정 사항

- 기존 몬BTI 영상 및 추가 참고 자료의 채택 범위
- 유형 수, 유형 이름과 무기별 기준값의 최종 보정
- 질문 수와 실제 질문 문구, 별도 ‘잘 모르겠다’ 응답의 추가 여부
- 사용자 테스트를 통한 질문 가중치·무기 축 값의 보정
- 추천 이유 등 결과 설명 문구
- 디자인, 이미지
- 와일즈 내 어떤 업데이트 시점의 특성을 기준으로 할지

## 현재 단계의 완료 조건

- 확정 방향이 README와 기획 문서에 일치하게 기록되어 있다.
- 사용자 제공 참고 자료가 제목과 링크만 있는 단순한 목록으로 등록되어 있다.
- Codex와 Claude가 공통 지침으로 작업할 수 있다.
- 로컬 개발·테스트·빌드와 GitHub Pages 배포 워크플로가 준비되어 있다.
- 시트 데이터를 검증·변환한 JSON으로 질문에 답하고 결과 화면(1~3순위·차트·영상·공유)을 확인할 수 있다. 순위는 확정한 추천 공식으로 계산한다.

다음 개발 단계는 기획자 응답 시나리오 테스트이며, 이후 지인 테스트 결과로 질문 가중치와 무기 특성값을 한 층씩 보정합니다.
