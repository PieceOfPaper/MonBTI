# 페르소나 테스트 기획

- 상태: 기획 확정, 구현 완료
- 최신 방향 반영일: 2026-10-11
- 실행 방법: [개발 및 AI 협업](development.md#페르소나-테스트)
- 대상: 몬스터헌터 와일즈 검사

## 목적

질문·무기 값·추천 공식이 바뀌었을 때 계산이 동작한다는 사실만 확인하지 않고, 의도한 성향의 사용자가 납득할 수 있는 무기를 추천받는지 반복해서 검증합니다.

페르소나 테스트는 다음 문제를 찾는 데 사용합니다.

- 질문에 의도한 대로 답해도 예상한 사용자 축 점수가 만들어지지 않는 문제
- 축 점수는 적절하지만 추천 공식이나 무기 값 때문에 예상과 다른 무기가 나오는 문제
- 일부 무기가 매우 좁은 영역에서만 추천되거나 다른 무기와 지나치게 겹치는 문제
- 작은 응답 변화로 추천 결과가 과도하게 바뀌는 문제
- 시트 갱신 전후에 의도하지 않은 추천 결과 회귀가 생기는 문제

이 문서는 자동화된 기획자 테스트의 사양입니다. 실제 사람이 질문을 이해하고 결과에 납득하는지는 별도의 지인 테스트로 확인합니다.

## 기본 원칙

1. **다섯 축을 모두 지정합니다.** 특정 축에 관심이 없더라도 제외하지 않고 중간값 `50`을 사용합니다.
2. **축 점수 직접 테스트와 실제 답변 테스트를 분리합니다.** 전자는 무기 값·추천 공식을, 후자는 질문 가중치·정규화까지 포함한 전체 흐름을 검증합니다.
3. **프로덕션 계산 함수를 그대로 사용합니다.** 테스트 전용 추천 공식이나 점수 계산식을 복사해서 만들지 않습니다.
4. **추천 비율을 균등하게 만드는 것이 목적은 아닙니다.** 14개 무기가 각각 같은 비율로 나와야 한다고 가정하지 않습니다.
5. **결과 변경을 곧바로 오류로 간주하지 않습니다.** 의도적인 데이터 보정으로 결과가 바뀔 수 있으므로 변경 이유를 확인하고 기대값을 갱신합니다.
6. **한 번에 한 층을 조정합니다.** 문구, 질문 가중치, 무기 값, 추천 공식을 동시에 바꾸지 않습니다.
7. 테스트는 배포에 포함되는 `src/data/wilds/*.json`을 읽습니다. 시트 수정 뒤에는 데이터 변환을 먼저 실행해야 최신 원본을 검사할 수 있습니다.

## 테스트 단계

### 1. 계산 계약 테스트

기존 단위 테스트를 유지하고 다음 계산 규칙을 검증합니다.

- 응답 1~6과 계수 `-1, -0.6, -0.2, 0.2, 0.6, 1`
- 양수·음수 질문 가중치의 방향
- 축별 가중치 절댓값 합을 사용하는 0~100 정규화
- `attack`·`counter`의 절대 차이
- `freedom`의 부족분 100%·초과분 50% 감점
- `complexity`·`management`의 초과 부담 100%·낮은 요구 50% 감점
- 최종 합산 가중치: `attack`·`counter` 0.75, `freedom`·`complexity`·`management` 1.0
- 최종 점수, 최대 단일 축 불일치, 시트 행 순서의 동점 처리
- 답변 수정 시 기존 값 교체 및 중복 누적 방지

이 단계는 계산 규칙이 코드 변경으로 달라지면 실패해야 합니다.

### 2. 축 점수 직접 입력 페르소나

페르소나의 목표 축 점수를 `rankWeapons()`에 직접 전달합니다. 질문과 답변 변환을 통하지 않으므로 무기 값과 추천 공식만 검증합니다.

각 페르소나는 다섯 축을 모두 가져야 합니다.

```js
{
  id: 'simple_reactive',
  name: '단순·즉응형',
  description: '짧은 행동을 자주 바꾸며 별도 관리가 적은 방식을 선호한다.',
  targetProfile: {
    attack: 15,
    freedom: 90,
    complexity: 25,
    management: 25,
    counter: 15,
  },
  expected: {
    directTop1: ['light_bowgun'],
    directTop3Includes: ['light_bowgun'],
  },
}
```

`directTop1`은 결과 변경을 허용할 후보를 배열로 둡니다. 경계에 있는 페르소나는 두 무기 이상을 허용할 수 있습니다. `directTop3Includes`는 반드시 상위 3개 안에 들어와야 하는 핵심 후보만 기록합니다.

### 3. 실제 문항 응답 페르소나

같은 페르소나의 목표 축 점수에 가까워지도록 현재 질문의 1~6 응답을 자동으로 찾습니다. 찾은 답변을 `computeAxisTotals()`와 `computeAxisProfile()`에 넣어 실제 사용자 프로필을 만들고 추천 결과를 계산합니다.

이 단계는 다음 두 가지를 따로 판정합니다.

- **프로필 재현:** 실제 답변으로 만든 축 점수가 목표 축 점수와 허용 오차 안에 있는가?
- **추천 유지:** 직접 입력 프로필과 실제 답변 프로필의 핵심 추천이 일치하는가?

초기 허용 오차는 다음과 같이 둡니다.

- 축별 절대 오차: 최대 `5`
- 다섯 축 평균 절대 오차: 최대 `3`
- 목표가 현재 질문의 이산적인 응답 조합으로 재현 불가능하면 가장 가까운 프로필과 오차를 보고하고 페르소나 값을 조정합니다.

자동 탐색 결과는 테스트 실행마다 같아야 합니다. 같은 오차의 답변 후보가 여러 개면 질문 순서에 따른 응답 배열의 사전순으로 하나를 선택합니다.

### 4. 무기 기준점 검사

각 무기의 다섯 기준값을 그대로 사용자 프로필로 사용합니다. 해당 무기는 모든 축이 정확히 일치하므로 100점으로 1순위가 되어야 합니다.

- 무기 14개를 데이터에서 자동으로 순회합니다.
- 해당 무기가 1순위가 아니면 중복 무기 값이나 정렬·계산 오류로 처리합니다.
- 두 무기의 다섯 값이 완전히 같아진 경우에는 먼저 나온 무기가 동점 규칙으로 선택되므로 중복을 별도로 명확하게 보고합니다.

이 테스트는 추천 영역의 넓이를 보장하지 않습니다. 무기가 최소한 자신의 기준점에서 선택 가능한지만 확인합니다.

### 5. 인접값 안정성 검사

대표 페르소나의 각 축을 한 번에 하나씩 `-10, -5, +5, +10`만큼 바꾸고 0~100으로 제한한 뒤 결과를 다시 계산합니다.

다음 내용을 보고합니다.

- 1순위가 유지되는 범위
- 처음으로 1순위가 바뀐 축과 방향
- 기준 결과와 상위 3개의 공통 무기 수
- 새로 들어오거나 빠진 무기
- 1순위와 2순위의 점수 차이

초기에는 경계 자체를 실패로 만들지 않습니다. 다만 ±5 변화에서 상위 3개가 하나도 겹치지 않거나, 동일 프로필에서 실행마다 결과가 달라지면 실패합니다.

### 6. 추천 영역 분포 검사

다섯 축의 0~100 공간을 일정 간격으로 순회해 각 무기의 1순위·상위 3위 비율을 계산합니다.

- 자동 테스트 기본 간격: `10` — 총 `11⁵ = 161,051`개 프로필
- 상세 수동 분석 간격: `5` — 총 `21⁵ = 4,084,101`개 프로필
- 각 축은 서로 독립적이고 균등한 가상 프로필로 생성합니다.
- 이 비율은 실제 사용자 분포가 아니라 추천 공식이 차지하는 **기하학적 추천 영역**입니다.

초기 경고 기준은 다음과 같습니다.

| 조건 | 처리 |
| --- | --- |
| 1순위가 한 번도 되지 않음 | 실패 |
| 상위 3위에 한 번도 들지 않음 | 실패 |
| 1순위 비율 1% 미만 | 경고 |
| 상위 3위 비율 5% 미만 | 경고 |
| 1순위 비율 20% 초과 | 경고 |
| 상위 3위 비율 45% 초과 | 경고 |

경고는 테스트와 데이터 갱신을 막지 않습니다. 현재 차지액스처럼 의도적으로 좁은 영역을 가질 수 있으므로 수치만 보고 무기 값을 바꾸지 않고, 인접 무기와의 겹침·승리 조건·실제 지인 테스트를 함께 확인합니다.

## 초기 대표 페르소나

아래 값은 테스트 구현을 시작하기 위한 기준점입니다. 2026-10-11 원본 시트 값을 데이터 JSON에 반영한 뒤 실제 순위를 다시 계산했고, 균형형을 제외한 7개 페르소나의 직접·응답 1순위가 모두 표의 대표 후보 안에 들어 그 후보를 `tests/personas/wilds-personas.js`의 기대값으로 확정했습니다. 고난도 관리형은 차지액스만, 나머지는 표의 후보 모두를 상위 3위 필수 후보로 둡니다.

| ID | 이름 | 한방 | 자유 | 복잡 | 관리 | 반격 | 의도한 대표 후보 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| `simple_reactive` | 단순·즉응형 | 15 | 90 | 25 | 25 | 15 | 라이트보우건·한손검 |
| `heavy_simple` | 묵직한 단순형 | 90 | 30 | 25 | 10 | 25 | 대검·해머 |
| `counter_guard` | 반격 수비형 | 25 | 60 | 35 | 15 | 95 | 랜스 |
| `complex_manager` | 고난도 관리형 | 70 | 40 | 90 | 90 | 75 | 차지액스·슬래시액스 |
| `mobile_manager` | 기동 관리형 | 60 | 80 | 65 | 85 | 10 | 조충곤 |
| `balanced` | 균형형 | 50 | 50 | 50 | 50 | 50 | 특정 무기 고정 전 현재 순위 검토 |
| `morph_pressure` | 변형 압박형 | 85 | 40 | 70 | 80 | 70 | 슬래시액스 |
| `mobile_counter` | 자유 반격형 | 35 | 85 | 45 | 65 | 75 | 활 |

`balanced`는 중간값에 가까운 무기가 무엇인지 관찰하는 기준점입니다. 특정 무기를 정답으로 만들기 위해 무기 값을 조정하지 않습니다.

## 페르소나 데이터 형식

구현 파일에서는 다음 필드를 사용합니다.

```js
{
  id: 'complex_manager',          // 고유한 영문 snake_case
  name: '고난도 관리형',           // 보고서 표시명
  description: '...',             // 성향 설명
  targetProfile: {                // 다섯 축 모두 필수, 0~100
    attack: 70,
    freedom: 40,
    complexity: 90,
    management: 90,
    counter: 75,
  },
  tolerance: {                    // 생략 시 공통 기본값 사용
    maxAxisError: 5,
    meanAbsoluteError: 3,
  },
  expected: {
    directTop1: ['charge_blade', 'switch_axe'],
    directTop3Includes: ['charge_blade'],
    answerTop1: ['charge_blade', 'switch_axe'],
    answerTop3Includes: ['charge_blade'],
  },
}
```

검증 규칙은 다음과 같습니다.

- `id`는 중복될 수 없습니다.
- `targetProfile`은 다섯 축을 빠짐없이 포함하고 각 값은 0~100의 유한한 숫자여야 합니다.
- 기대 무기 ID는 현재 무기 데이터에 존재해야 합니다.
- `directTop1`·`answerTop1` 후보 중 하나가 실제 1순위면 통과합니다.
- `*Top3Includes`의 모든 무기는 실제 상위 3개에 포함되어야 합니다.
- 기대값을 비워 둔 페르소나는 관찰용으로 처리하고 결과를 보고하되 추천 결과 때문에 실패시키지 않습니다.

## 응답 자동 탐색

### 목표 함수

후보 답변으로 만든 사용자 프로필을 `P`, 페르소나 목표를 `T`라고 할 때 다음 값을 최소화합니다.

```text
axisError(a) = |P[a] - T[a]|
meanAbsoluteError = Σ axisError(a) / 5
```

우선순위는 다음과 같습니다.

1. 최대 축 오차가 작은 후보
2. 평균 절대 오차가 작은 후보
3. 응답 배열이 사전순으로 앞선 후보

### 현재 질문에 대한 구현

현재 20문항은 각 문항이 하나의 축만 측정하므로 축별로 독립 탐색할 수 있습니다.

1. 축에 영향을 주는 질문을 모읍니다.
2. 해당 축의 모든 응답 조합을 생성합니다. 축별 4문항이면 `6⁴ = 1,296`개입니다.
3. 프로덕션 계산 함수로 축 점수를 계산합니다.
4. 목표값과 가장 가까운 조합을 선택합니다.
5. 다섯 축에서 선택한 응답을 하나의 전체 답변 객체로 합칩니다.

한 문항이 여러 축에 영향을 주도록 바뀌면 축별 독립 탐색을 사용할 수 없습니다. 구현은 이를 자동 감지해 명확한 오류를 내고, 이후 전체 문항 빔 탐색 또는 명시적인 답변 fixture 방식으로 전환합니다. 다축 문항을 잘못 독립 계산해서 조용히 틀린 답을 만들면 안 됩니다.

## 구현 구조

Claude Code는 아래 구조를 기준으로 구현합니다. 실제 저장소 상태에 따라 이름을 조금 조정할 수 있지만 역할은 유지합니다.

```text
tests/
  personas/
    wilds-personas.js       # 대표 페르소나 fixture
    answer-search.js        # 목표 프로필에 가까운 응답 탐색
    persona-runner.js       # 직접 점수·응답 점수·추천·오차 계산
    persona.test.js         # CI에서 실패시킬 계약과 기대 결과
scripts/
  persona-report.js         # 분포·경계·순위 결과를 사람이 읽는 형태로 출력
```

사용할 프로덕션 모듈은 다음과 같습니다.

- `src/core/scoring.js`: `computeAxisTotals()`, `computeAxisProfile()`
- `src/core/recommend.js`: `scoreWeapon()`, `rankWeapons()`, `recommendWeapons()`
- `src/core/axes.js`: 축 ID와 표시 순서
- `src/data/wilds/questions.json`: 배포 질문 데이터
- `src/data/wilds/weapons.json`: 배포 무기 데이터

테스트 코드에 응답 계수, 정규화식, 축별 불일치 공식을 다시 구현하지 않습니다.

## 명령

다음 명령이 `package.json`에 있습니다.

```sh
npm run test:personas
npm run analyze:personas
npm run analyze:personas -- --step 5
```

- `test:personas`: 페르소나 fixture, 답변 재현 오차, 기대 추천과 기본 불변조건을 Vitest로 검증합니다.
- `analyze:personas`: 페르소나별 직접/응답 프로필과 순위, 인접값 변화, 기본 간격 10의 추천 영역을 출력합니다.
- `--step 5`: 더 정밀하지만 오래 걸리는 추천 영역 분석입니다.
- `--save <파일>`: 추천 영역 분포를 기준 결과 JSON으로 저장합니다. `--baseline <파일>`: 저장한 기준 결과와 무기별 비율 증감을 함께 출력합니다.
- 분석 명령은 아래 실패 항목이 하나라도 있으면 종료 코드 1로 끝납니다.

일반 `npm test`에서도 `persona.test.js`를 실행합니다. 분포 전체 순회와 상세 보고서는 일반 단위 테스트에 넣지 않고 분석 명령에서 실행합니다.

## 보고서 출력

분석 명령은 다음 정보를 출력합니다.

### 페르소나별

- ID와 이름
- 목표 프로필
- 자동 생성한 실제 프로필
- 축별 오차와 평균 절대 오차
- 자동 생성한 질문별 응답
- 직접 프로필의 1~5순위와 원점수
- 실제 응답 프로필의 1~5순위와 원점수
- 1순위와 2순위의 점수 차이
- 인접값 검사에서 결과가 처음 바뀐 축과 방향

### 전체 분포

- 데이터의 `format_version`, `exported_at`, `converted_at`
- 사용한 간격과 전체 프로필 수
- 무기별 1순위 횟수·비율
- 무기별 상위 3위 횟수·비율
- 이전에 저장한 기준 결과가 있다면 증감
- 경고 기준에 걸린 무기

부동소수 점수는 계산 중 반올림하지 않습니다. 보고서에서만 소수 둘째 자리까지 표시합니다.

## 실패와 경고

### 자동 테스트를 실패시키는 항목

- 페르소나 데이터 형식 오류
- 목표 프로필을 허용 오차 안에서 재현하지 못함
- 확정한 기대 1순위·상위 3위 조건 불충족
- 무기가 자신의 기준점에서 1순위가 되지 못하거나 다섯 값이 같은 무기가 있음
- 같은 입력에서 결과가 달라짐
- ±5 인접값에서 기존 상위 3개와 공통 무기가 하나도 없음
- 추천 영역 순회에서 어떤 무기가 한 번도 1순위 또는 상위 3위가 되지 않음 — 분석 명령에서만 판정합니다. 일반 테스트에서는 무기 기준점 검사로 각 무기가 최소 한 지점에서 1순위가 되는지 확인합니다.

### 경고만 출력하는 항목

- 무기별 추천 비율이 초기 경고 범위를 벗어남
- 1·2순위 점수 차이가 매우 작아 경계에 가까움 — 초기 기준은 1점 미만
- ±5 변화만으로 1순위가 변경됨
- 직접 프로필과 응답 프로필의 1순위는 다르지만 허용 후보 안에 있음

## 데이터 변경 절차

질문 문구·가중치 또는 무기 값을 바꿀 때 다음 순서를 따릅니다.

1. 원본 시트를 수정합니다.
2. `npm run data:convert`로 최신 JSON을 생성합니다.
3. 기존 단위 테스트를 실행합니다.
4. 페르소나 테스트와 분석 보고서를 실행합니다.
5. 이전 결과와 달라진 페르소나·무기 비율을 확인합니다.
6. 의도한 변화라면 기대값을 수정하고 변경 이유를 결정 기록이나 커밋 설명에 남깁니다.
7. 의도하지 않은 변화라면 문구 → 질문 가중치 → 무기 값 → 추천 공식 순서로 원인을 분리합니다.
8. `npm test`와 `npm run build`를 통과한 뒤 반영합니다.

원본 시트만 수정하고 JSON을 갱신하지 않은 상태에서는 테스트 결과를 최신 기획의 결과로 해석하지 않습니다.

## 지인 테스트로 확장

자동 페르소나 테스트가 안정된 뒤 실제 입문자와 기존 유저를 구분해 기록합니다.

최소 기록 항목은 다음과 같습니다.

- 테스트 날짜와 데이터 버전
- 입문자·기존 유저 구분
- 실제 답변과 계산된 다섯 축 점수
- 추천 1~3순위
- 상위 3개 중 사용해 보고 싶은 무기
- 결과가 본인 성향과 맞는다고 느끼는 정도
- 추천 무기를 실제로 사용한 뒤의 만족도
- 이해하기 어려웠거나 한쪽 답을 유도한다고 느낀 질문
- 만족·불만족 이유

소수의 지인 결과는 통계적 정확도를 증명하는 자료가 아니라 질문 오해와 추천 괴리를 찾는 초기 보정 자료로 사용합니다.
