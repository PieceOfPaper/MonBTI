- 대체 상태: 질문의 선택지 행·응답별 기준값 구조는 DEC-014로 대체됨. 무기 탭과 정적 JSON 참조 방식은 유지함.

- 초기 데이터: 무기 14개의 모든 축에 수정 가능한 임시값 50을 넣는다. 질문 하나에 공격 성향 0·100의 선택지 두 개를 넣고 나머지 축은 비운다. 임시 여부를 구분하는 필드는 두지 않는다.

- 이유 및 영향: 원본 시트에서 데이터를 편집하고, 사이트에는 검토한 정적 데이터를 제공한다. 행 번호 대신 고유 ID, 열 위치 대신 열 이름으로 읽는다.

## 2026-10-05 — 공통 6단계 응답과 질문당 한 행 구조 확정

- ID: DEC-014
- 상태: 공통 6단계 응답·질문당 한 행·분기 없는 흐름은 유지. 단일 축·axis·reverse·0~100 환산·산술평균은 DEC-015로 대체됨
- 근거: 사용자가 1~6단계 공통 응답 제안을 채택하고 개발 가능한 기획과 시트 수정을 요청함.
- 결정: 모든 질문에 동일한 여섯 동의 응답을 표시한다. 답변에 따라 질문을 분기하지 않고 질문당 축 하나를 측정한다.
- 질문 구조: question_id, question_order, question_text, axis, reverse. axis 값은 attack·freedom·combo·resource·counter 중 하나이며 reverse는 정·역방향을 나타내는 불리언이다.
- 환산: 정방향은 20 × (응답 - 1), 역방향은 100 - 정방향 값. 각 축은 해당 축 문항들의 산술평균으로 계산하며 첫 구현에서는 문항별 가중치를 두지 않는다.
- 영향: 선택지 행과 질문별 0~100 입력 열을 제거하고 예시 질문을 정방향 평서문 하나로 바꾼다. 무기 탭의 다섯 기준값은 그대로 유지한다. 미측정 축과 무응답을 0이나 50으로 채우지 않는다.
- 미정: ‘잘 모르겠다’ 추가 여부, 실제 질문 수·문구, 무기 비교 공식·추천 가중치·동점 처리·결과 구성.
- 관련 문서: README.md, docs/project-plan.md, docs/test-design.md, docs/data-schema.md, AGENTS.md
- 대체한 결정: DEC-013의 질문 선택지 행 구조와 응답별 기준값 정의. 무기 입력 및 시트 원본·JSON 배포 흐름은 유지함.

## 2026-10-05 — 다축 가중치와 부호 있는 응답 계산

- ID: DEC-015
- 상태: 설계·원본 시트 반영 완료, 사이트 구현 완료(DEC-016)
- 근거: 사용자가 한 질문으로 다양한 축을 측정하도록 모든 기준을 필드로 받고, 동의 정도와 입력값의 부호로 기여도를 계산하도록 요청함.
- 결정: Wilds_Question은 question_id, question_order, question_text, attack, freedom, combo, resource, counter를 사용한다. 질문당 한 행과 공통 1~6단계 응답을 유지하며 한 문항에 여러 축의 가중치를 지정할 수 있다.
- 입력: 질문 가중치는 -100~100이며 양수·음수로 방향, 절댓값으로 영향 크기를 정한다. 0·빈칸은 영향 없음이며 빈칸은 변환 시 0으로 통일한다. 문항마다 최소 하나의 0이 아닌 가중치가 필요하다.
- 계산: 응답 1~6의 계수는 -1·-0.6·-0.2·0.2·0.6·1이다. 축별 기여도는 가중치 × 응답 계수이며, 답변 문항의 기여도를 축별로 합산한다. 음수 가중치는 방향을 반대로 바꾼다.
- 예시: attack 100·freedom 50인 문항에 매우 동의하면 +100·+50, 전혀 동의하지 않으면 -100·-50이다.
- 영향: axis·reverse와 체크박스·축 드롭다운을 제거한다. 예시 질문을 다축 문항 하나로 수정한다. 무기 탭의 0~100 특성값과 14개 임시값은 유지한다.
- 미측정·수정: 해당 축에 0이 아닌 가중치가 있는 답변 문항이 없으면 null이다. 기여도가 상쇄된 합계 0은 유효하다. 답변 수정 시 현재 답변에서 재계산한다.
- 미정: 합산값의 비교용 정규화, 무기 비교 공식·추천 가중치·동점 처리·결과 구성, 실제 질문 수·문구, ‘잘 모르겠다’ 추가 여부.
- 이유: 단일 축 문항만으로 제한하지 않고 한 질문의 여러 플레이 특성을 서로 다른 강도와 방향으로 반영하기 위해서다.
- 관련 문서: README.md, docs/project-plan.md, docs/test-design.md, docs/data-schema.md, AGENTS.md
- 대체한 결정: DEC-014의 단일 축 필드와 환산·평균 규칙. 공통 응답·질문당 한 행·정적 JSON 배포 흐름은 유지한다.

- 영향: 다운로드·검증·테스트·빌드 실패 시 커밋과 배포를 중단한다. 데이터 변경이 없으면 커밋 없이 다시 배포한다. 기존 배포와 동시 실행 그룹을 공유하고, 기존 배포도 실행 시점의 최신 `main`을 사용한다. 원본 시트의 공유 설정과 사이트의 응답·계산 규칙은 변경하지 않는다.

## 2026-10-06 — 다섯 선택 기준의 평가 의미 구체화

## 2026-10-06 — 질문 가중치 입력 기준과 기존 문항 재검토

- ID: DEC-021
- 상태: 가이드 반영 및 원본 시트 재검토 완료
- 근거: 질문마다 실제 축 가중치를 어떤 규칙으로 정할지 일관된 기준이 필요해졌고, 사용자가 해당 기준을 질문 가이드에 추가한 뒤 기존 질문을 다시 검토하도록 요청함.
- 결정: 가중치의 부호는 동의할수록 축이 움직이는 방향, 절댓값은 동의·비동의가 축의 양쪽을 구분하는 근거 강도로 정의한다. 25단위 값을 기본으로 사용하고 100·75·50·25·0의 적용 조건을 구분한다.
- 다축 규칙: 기본적으로 주축 하나를 사용하고 명확한 경우에만 보조축 하나를 추가한다. 축마다 연결 이유를 따로 설명할 수 없는 값은 0으로 두며, 세 축 이상이나 여러 높은 가중치가 필요한 질문은 범위가 과도한지 재검토한다.
- 재검토: Wilds_Question 25개를 같은 기준으로 검토했다. 연속되는 과정의 재미를 콤보로 본 문항과 축적·아껴 쓰기를 자원 부담으로 본 문항을 현재 축 정의에 맞게 교체하고, 근거가 약한 보조축을 제거했다. 가중치는 설명 가능한 25단위로 정리했으며 ID와 표시 순서는 유지했다.
- 영향: 질문의 의미·분류·가중치는 원본 시트에서 변경되며, 사이트 데이터에는 시트 데이터 갱신 워크플로를 실행한 뒤 반영된다. 공통 1~6 응답과 계산식은 바뀌지 않는다.
- 관련 문서: docs/question-guide.md, docs/test-design.md, docs/data-schema.md
- 대체한 결정: DEC-018의 질문 작성 가이드를 확장하고 DEC-020의 축 정의를 실제 가중치 판단 규칙에 적용한다.
