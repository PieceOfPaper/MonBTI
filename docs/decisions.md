## 2026-10-05 — 무기 선택 기준 확정

- ID: DEC-011
- 상태: 확정
- 근거: 사용자가 무기 선택 기준을 압축하고 추가 축의 채택·제외 범위를 지정한 뒤, 기획서 반영을 요청함.
- 결정: 공격 성향, 자유도, 콤보 의존, 자원 부담, 카운터 의존의 다섯 축을 사용한다. 손에 익숙해질 수 있는 플레이 특성을 우선한다.
- 이유: 입문자의 무기 적응에 영향을 주는 기준으로 선택 부담을 설명하기 위해서다.
- 영향: 공격 성향은 지속형과 한방형 사이의 성향이며 공격 속도와 구분한다. 나머지 네 축은 정도의 높고 낮음을 평가한다. 카운터 기술의 유무보다 카운터 중심 플레이의 필요성을 평가한다.
- 제외 범위: 주관적인 멋짐, 공통적인 패턴 학습·상황 판단, 별도의 방어 방식 분류, 별도의 입력 복잡도, 콤보 입력 순서와 특수 입력 예외, 조준·거리 유지 부담.
- 관련 문서: README.md, docs/project-plan.md, docs/test-design.md, AGENTS.md
- 대체한 결정: 없음. 앞서 제안된 다른 축은 확정 기획으로 채택하지 않음.
- 남은 미정 사항: 무기별 축 평가, 문항, 수치화, 점수·가중치, 유형 및 결과 구성.

## 2026-10-05 — 시트 원본과 와일즈 데이터 입력 구조 준비

- ID: DEC-013
- 상태: 원본·입력 규격 확정, 변환·사이트 연동 구현 대기
- 근거: 사용자가 MonBTI_테이블을 앞으로의 데이터 원본으로 지정하고 와일즈 무기·질문 탭, 더미 무기 데이터, 예시 질문 하나 및 기획서 반영을 요청함.
- 결정: 기존 스프레드시트에 Wilds_Weapon과 Wilds_Question을 추가한다. 무기는 무기당 한 행, 질문은 선택지당 한 행으로 관리하고 질문 ID로 묶는다.
- 필드 이름: 다섯 기준은 attack, freedom, combo, resource, counter로 통일한다. 사용자의 후속 요청에 따라 긴 접미사와 임시 구분·메모 필드를 제거한다.
- 초기 입력 규격: 다섯 축은 0~100. 공격 성향은 0이 지속형, 100이 한방형이다. 나머지 축은 값이 높을수록 해당 특성의 정도가 높다. 질문에서 측정하지 않는 축은 빈칸이며 0과 구분한다.
- 초기 데이터: 무기 14개의 모든 축에 수정 가능한 임시값 50을 넣는다. 질문 하나에 공격 성향 0·100의 선택지 두 개를 넣고 나머지 축은 비운다. 임시 여부를 구분하는 필드는 두지 않는다.
- 참조 방식: 원본 XLSX를 내보내고 검증·JSON 변환 후 저장소에 반영해 GitHub Pages로 배포하는 방식을 기본으로 한다. 공유 설정은 변경하지 않으며 원본 수정의 실시간 반영은 구현하지 않는다.
- 이유 및 영향: 원본 시트에서 데이터를 편집하고, 사이트에는 검토한 정적 데이터를 제공한다. 행 번호 대신 고유 ID, 열 위치 대신 열 이름으로 읽는다.
- 관련 문서: README.md, docs/project-plan.md, docs/test-design.md, docs/data-schema.md, docs/README.md, AGENTS.md
- 대체한 결정: DEC-011의 수치 범위 미정 부분을 초기 입력 규격 0~100으로 구체화한다. 실제 무기별 기준값과 추천 계산은 계속 미정이다.
