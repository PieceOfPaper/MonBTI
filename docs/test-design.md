# 검사 및 무기 추천 설계

- 상태: 선택 기준·6단계 응답·축별 집계 규칙 확정 및 구현, 결과 화면 구성 구현(추천은 임시 무작위), 실제 문항·무기 추천 계산 설계 대기
- 최신 방향 반영일: 2026-10-06

## 확정된 설계 조건

- 기준 작품을 선택한 다음 검사합니다. 현재는 와일즈만 지원합니다.
- 입문자가 게임 지식 없이 답할 수 있어야 합니다.
- 입문자의 무기 선택에 도움을 주고, 기존 유저에게는 재미를 제공합니다.
- 질문에 답하는 MBTI 검사와 비슷한 경험을 지향합니다.
- 멋짐 등 주관적인 인상보다 손에 익숙해질 수 있는 플레이 특성을 기준으로 합니다.
- 참고 자료의 세부 채택 범위와 무기별 평가는 미정입니다.

## 확정된 무기 선택 기준

| 축 이름 | 영문명·필드 이름 | 짧은 표기 | 평가 내용 |
| --- | --- | --- | --- |
| 공격 성향 | attack | 한방 | 자주 대미지를 누적하는 방식과 준비한 기회에 큰 대미지를 집중하는 방식 사이의 성향 |
| 자유도 | freedom | 자유 | 행동 중 이동·방향 전환·취소와 다른 대응으로의 전환이 자유로운 정도 |
| 콤보 의존 | combo | 연계 | 제 성능을 내기 위해 여러 동작과 운용 구조를 익히고 유지해야 하는 정도 |
| 자원 부담 | resource | 자원 | 전투 중 자원의 상태를 확인·유지·보충하며 관리해야 하는 정도 |
| 카운터 의존 | counter | 반격 | 몬스터의 행동에 맞춘 카운터를 주된 운용으로 성공시켜야 하는 정도 |

공격 성향은 두 스타일 사이의 성향으로 다룹니다. 나머지 네 축은 정도가 높고 낮은 구조로 다룹니다.
결과 화면·차트·공유 이미지에서는 짧은 표기 **한방·자유·연계·자원·반격**을 이 순서로 사용합니다. 한방은 값이 높을수록 한방형, 낮을수록 지속형입니다. 화면에는 기준별 설명 문구를 따로 두지 않습니다.
무기 기준값은 0~100이며, 질문 가중치는 -100~100입니다. 사용자 응답의 축별 기여도는 부호 있는 합산값으로 계산합니다. 무기별 기준값은 참고 자료를 바탕으로 입력했지만 계속 보정할 수 있습니다. 합산값을 무기 특성과 비교하기 위한 정규화, 추천 가중치와 무기 비교 공식은 아직 정하지 않았습니다.
축별 영문명, 질문의 다섯 가중치 필드와 데이터 참조 규칙은 [시트 데이터 설계](data-schema.md)를 따릅니다.
축 사이에 관련성이 있더라도 각 축을 따로 평가하며, 한 축의 특성으로 다른 축의 점수를 자동으로 정하지 않습니다.
정도 자체를 무기의 강함이나 사용자의 실력으로 해석하지 않습니다.

### 공격 성향

- 낮을수록 짧은 기회를 자주 활용해 대미지를 계속 누적하는 지속형, 높을수록 준비·대기 후 얻은 기회에 큰 대미지를 집중하는 한방형에 가깝습니다.
- 공격 리듬과 타격감, 결과를 기다리는 시간, 한 번 성공했을 때의 보상과 실패했을 때 다시 준비해야 하는 부담을 함께 봅니다.
- 빠른 무기와 느린 무기를 나누는 축이 아닙니다. 공격 속도·모션 길이·타격 횟수 하나만으로 값을 정하지 않습니다.
- 큰 공격이 있어도 평소 운용의 중심이 지속적인 누적이라면 높게 평가하지 않고, 공격이 빨라도 특정 기회에 준비한 대미지가 집중된다면 높을 수 있습니다.

### 자유도

- 낮을수록 시작한 행동의 위치·방향·후속 행동이 고정되기 쉽고, 높을수록 진행 중인 행동을 상황에 맞게 조정하거나 다른 대응으로 바꾸기 쉽습니다.
- 공격 중 원하는 방향으로 이동하거나 방향을 바꿀 수 있는지, 공격을 취소하거나 짧게 끝내고 회피·가드·다른 공격으로 넘어가기 쉬운지를 포함합니다.
- 입문자가 몬스터의 변화에 길게 계산하지 않고 그때그때 대응할 수 있는지를 봅니다. 행동을 정한 뒤 기다려야 하거나 끝날 때까지 다른 선택을 하기 어려운 부담은 자유도를 낮춥니다.
- 단순 이동 속도, 평소 계획에서 샛길로 빠지는 성격, 잠깐 다른 일을 했다 돌아오는 생활 습관과는 구분합니다.

### 콤보 의존

- 낮을수록 몇 가지 기본 동작만 알아도 역할을 수행하기 쉽고, 높을수록 여러 동작·파생·운용 조건을 익혀야 제 성능을 내기 쉽습니다.
- 필요한 동작을 놓치거나 운용 흐름이 끊겼을 때 생기는 손실, 다시 유효한 상태로 돌아가는 부담, 익숙해지기까지 필요한 연습량을 포함합니다.
- 단순히 행동이 이어지는 과정 자체를 좋아하는 성향, 새로운 활용법을 발견하는 즐거움, 선택지가 많은 자유도를 뜻하지 않습니다. 정해진 운용 구조가 복잡하고 숙련을 요구하는 경우에도 높을 수 있습니다.
- 모든 무기에 콤보가 있다는 사실이나 콤보 길이만으로 값을 높이지 않습니다. 콤보 없이도 기본 역할을 충분히 수행할 수 있다면 낮게 평가합니다.
- 조작 적응에 관한 부담은 이 항목에서 다루지만, Xbox 패드의 Y·B 동시 입력 같은 버튼 조합이나 커맨드를 순서대로 입력하는 난도는 별도 평가하지 않습니다. 특수 입력 예외도 제외합니다.

### 자원 부담

- 낮을수록 공격 자체에 집중해도 자원이 자연스럽게 충당되거나 영향이 작고, 높을수록 전투 중 하나 이상의 상태를 계속 확인하고 유지·소비·보충해야 합니다.
- 남은 양과 지속 시간의 확인 빈도, 여러 상태의 동시 관리, 성능을 유지하기 위한 별도 행동, 부족하거나 유지에 실패했을 때의 손실을 포함합니다.
- 무언가를 모으거나 축적하는 것을 좋아하는 성향, 아껴 두었다가 쓰는 성격을 직접 평가하는 축이 아닙니다. 축적은 실제 전투에서 계속 관리해야 할 때만 이 축의 근거가 됩니다.
- 자원이 존재해도 자연스럽게 넘치거나 평소 운용만으로 자동 보충되어 별도로 신경 쓸 필요가 없다면 부담을 높이지 않습니다.
- 퀘스트 전 장비·아이템 준비보다 전투 중 반복되는 관리 부담을 우선합니다. 준비 요소도 전투 운용과 계속 연결될 때만 포함합니다.

### 카운터 의존

- 낮을수록 카운터 없이도 회피·가드·선제 공격 등으로 주된 역할을 수행할 수 있고, 높을수록 몬스터의 신호와 타이밍에 맞춘 카운터 성공이 핵심 운용이 됩니다.
- 카운터 기술의 보유 여부가 아니라 사용 빈도와 필요성을 봅니다. 선택적인 보조 수단이면 낮고, 카운터를 적극적으로 성공시켜야 성능·흐름·보상을 유지한다면 높습니다.
- 몬스터가 무언가를 할 때 정해진 대응을 정확한 때에 돌려주는 플레이 부담을 다룹니다. 일반적인 패턴 학습과 상황 판단 전체를 카운터 의존으로 계산하지 않습니다.
- 카운터 위주가 아닌 무기가 가드와 회피 중 무엇을 쓰는지는 이 축에서 다시 나누지 않습니다.

## 별도 평가에서 제외할 요소

- 멋짐과 외형 등 주관적인 인상은 현재 선택 기준에 포함하지 않습니다.
- 패턴 학습과 상황 판단은 모든 무기에 필요한 공통 요소로 보고 별도 축으로 두지 않습니다.
- 방어 방식을 가드·회피·카운터로 분류하는 대신 카운터 의존을 사용합니다.
- 입력 복잡도는 별도 축으로 두지 않으며, 콤보 입력 순서와 특수한 입력 예외도 평가하지 않습니다.
- 조준과 거리 유지 부담은 현재 검사에 포함하지 않습니다.

## 확정된 응답 및 성향 계산

- 모든 질문은 동일한 1~6단계 동의 척도를 사용합니다.
- 질문마다 다섯 축의 가중치를 입력하며, 한 질문이 여러 축에 서로 다른 강도·방향으로 영향을 줄 수 있습니다.
- 질문은 `question_order` 순서로 모든 사용자에게 동일하게 표시합니다. 답변에 따른 질문 분기는 사용하지 않습니다.
- 3과 4 사이가 중립점이며, 별도의 중립 선택지는 없습니다.
- 기본 응답은 아래 여섯 개입니다. ‘잘 모르겠다’는 별도 제안이며 추가 여부는 미정입니다.

| 응답 | 표시 문구 | 응답 계수 |
| --- | --- | --- |
| 1 | 전혀 그렇지 않다 | -1 |
| 2 | 그렇지 않다 | -0.6 |
| 3 | 조금 그렇지 않다 | -0.2 |
| 4 | 조금 그렇다 | +0.2 |
| 5 | 그렇다 | +0.6 |
| 6 | 매우 그렇다 | +1 |

### 환산과 집계

1. 응답은 정수 `r ∈ {1, 2, 3, 4, 5, 6}`로 저장합니다. 응답 문구나 화면 위치로 식별하지 않습니다.
2. 응답 계수는 `c(r) = (2 × r - 7) / 5`입니다.
3. 각 질문의 축별 기여도는 `해당 축의 가중치 × c(r)`입니다. 매우 동의하는 응답 6에서 입력한 가중치가 그대로 반영됩니다.
4. 양수 가중치는 동의 시 양수·비동의 시 음수로, 음수 가중치는 동의 시 음수·비동의 시 양수로 반영됩니다. `reverse` 필드는 두지 않습니다.
5. 가중치 0·빈칸은 해당 축에 영향을 주지 않습니다. 빈칸은 데이터 변환에서 0으로 통일합니다. 한 문항에 최소 하나의 0이 아닌 가중치가 있어야 합니다.
6. 사용자 축별 합산값은 답변한 모든 질문의 해당 축 기여도를 더한 값입니다. 문항별 평균이나 0~100 환산을 이 단계에서 적용하지 않습니다.
7. 해당 축에 0이 아닌 가중치가 있는 답변 문항이 하나도 없으면 `null`입니다. 측정된 기여도들이 상쇄된 합계 0은 유효한 계산값입니다.
8. 계산 중에는 반올림하지 않습니다. 답변 수정 시 기존 응답을 교체하고 현재 답변 전체에서 다시 계산해 중복 누적을 방지합니다.

가중치가 attack 100·freedom 50이면 아래처럼 반영합니다.

| 응답 | attack 기여도 | freedom 기여도 |
| --- | --- | --- |
| 1 | -100 | -50 |
| 2 | -60 | -30 |
| 3 | -20 | -10 |
| 4 | +20 | +10 |
| 5 | +60 | +30 |
| 6 | +100 | +50 |

attack을 -100으로 입력하면 위 attack 기여도의 부호가 모두 반대가 됩니다. 예시 질문의 나머지 축은 가중치 0이므로 측정되지 않습니다.
무응답은 응답 1과 다르며 합산에서 제외합니다. 초기에는 모든 문항 응답을 마친 뒤 결과 단계로 진행하도록 구현합니다.

합산값의 범위는 문항 수와 가중치에 따라 달라집니다. 무기 탭의 0~100 특성값과 직접 비교할 수 있는 척도로 확정한 것은 아닙니다. 최종 비교를 위한 축별 정규화·추천 계산은 후속 결정 사항입니다.

### 문항 작성 원칙

앞으로 질문을 만들거나 수정·검토할 때는 [질문 작성 가이드](question-guide.md)를 먼저 참고합니다.
몬헌 지식 없이 떠올릴 수 있는 일상 상황·행동 선호를 간접적으로 묻고, 문장의 뜻은 바로 이해할 수 있게 작성합니다.
하나의 응답을 여러 축으로 해석할 수 있지만, 서로 다른 답을 하고 싶은 독립된 주장들을 한 질문에 묶지 않습니다.
질문은 여섯 단계로 동의 정도를 답할 수 있는 평서문으로 작성합니다.
하나의 상황이나 플레이 선호가 여러 축과 관련되면 해당 축마다 가중치를 지정합니다. 문구와 각 축의 영향 방향이 명확한지 확인합니다.
동의할 때 축 값이 높아지면 양수, 낮아지면 음수로 입력합니다. 영향이 없으면 0 또는 빈칸으로 둡니다.
높은 값과 낮은 값의 의미는 위 다섯 축의 정의를 따릅니다.
부담이 높아도 괜찮다는 수용 정도와 부담이 높은 플레이 자체를 원하는 선호를 같은 의미로 작성하지 않습니다.

## 결정할 사항

| 항목 | 현재 상태 | 검토할 내용 |
| --- | --- | --- |
| 선택 기준 | 다섯 축·무기 특성값 0~100 | 현재 수치는 참고 자료 기반이며 최종 보정은 미정 |
| 데이터 원본 | 시트·열 구조·JSON 변환·사이트 연동 완료 | Wilds_Weapon, Wilds_Question |
| 유형 구조 | 미정 | 유형 코드·이름의 사용 여부, 유형과 무기 사이의 관계 |
| 문항 수 | 미정 | 설명 부담, 소요 시간, 중복 문항 |
| 답변 형식 | 1~6단계 동의 척도 확정 | 공통 여섯 응답, 중립 선택지 없음 |
| 사용자 성향 계산 | 질문별 다축 가중치 × 응답 계수의 축별 합산 | 질문 가중치 -100~100, 미측정 축은 null. 확정 정규화는 미정이며 차트에는 임시 0~100 환산 사용 |
| 잘 모르겠다 | 미정 | 도입 시 환산값 없이 집계에서 제외하는 방식 검토 |
| 추천 계산 | 미정, 임시 무작위 구현 | 유형별 배정, 무기별 점수, 성향과 무기 특성의 비교 등 |
| 동점 처리 | 미정 | 복수 추천, 추가 질문, 일관된 우선순위 등. 임시 무작위 선택에는 동점이 없음 |
| 결과 구성 | 1~3순위·차트·영상·공유 구현 | 추천 이유, 취향이 갈릴 부분 등 설명 문구 |
| 답변 수정·재검사 | 기본 동작 구현, 기획 미정 | 이전 질문 이동·결과에서 답변 수정·처음부터 다시 하기를 임시 구현. 수정 시 현재 답변 전체로 재계산 |
| 결과 공유 | 이미지·링크 공유 구현 | 링크 미리보기 이미지 등 추가 여부 |

위 다섯 축 외에 앞서 제안된 성향 축, 18~24문항, 성향 코드와 무기별 점수 조합은 확정 사항이 아닙니다.

## 기획할 때 사용할 작성 형식

### 무기별 특성

무기 ID, 표시 이름, 기준 작품·업데이트, 다섯 축의 평가와 이유, 플레이 특징, 입문자 설명, 근거 자료 링크, 검토 상태를 기록합니다.
모든 무기를 같은 항목으로 비교하되, 단순히 강한 무기를 선호 성향과 동일시하지 않습니다.

### 질문

질문 ID, 표시 순서, 평서문 본문과 다섯 축의 부호 있는 가중치(`attack`, `freedom`, `combo`, `resource`, `counter`)를 원본 시트에 기록합니다.
선택지 문구와 응답별 환산값은 공통 규칙을 사용하며 문항마다 반복 저장하지 않습니다.
실력이나 이미 쓰는 무기를 묻는 것과 플레이 취향을 묻는 것을 구분합니다.
일상적인 표현과 다축 해석의 검토 기준은 [질문 작성 가이드](question-guide.md)를 따릅니다.

### 결과

결과 ID, 무기 또는 유형, 짧은 소개, 추천 이유, 취향이 갈릴 특징, 근거 및 검토 상태를 기록합니다.
수치 표시를 도입하면 계산 방식과 의미를 함께 정합니다.

## 임시 결과 구성

추천 계산과 확정 정규화가 정해지기 전까지 사용하는 임시 규칙입니다. 확정 기획이 아니며, 추천 방식이 정해지면 대체합니다.

- **임시 무기 추천:** 기준값으로 계산하지 않고 무기 목록에서 서로 다른 무기 세 개를 무작위로 골라 1~3순위로 보여 줍니다. 시드는 현재 답변 전체(질문 ID·응답)로 만들어 같은 답변이면 새로고침해도 같은 결과가 나오고, 답변을 수정하면 다시 뽑습니다. 순위에는 의미가 없으며 결과 화면에 ‘추천 방식을 준비하는 동안 무작위로 고른다’고 안내합니다. 구현: `src/core/recommend.js`.
- **임시 0~100 환산:** 차트에서 무기 기준값(0~100)과 함께 보여 주기 위해 축별 합산값을 `50 + 50 × 합산값 ÷ 답변 문항 가중치 절댓값의 합`으로 바꿉니다. 모두 매우 동의하는 방향이면 100, 반대면 0, 상쇄되면 50입니다. 미측정 축은 null로 두어 차트 꼭짓점에서 빼고 표에는 ‘측정 안 됨’으로 표시합니다. 구현: `computeAxisProfile`(`src/core/scoring.js`).

## 현재 구현된 화면

아래는 현재 구현 상태입니다.

- 주소: `#/` 작품 선택, `#/wilds` 질문, `#/wilds/result` 결과, `#/wilds/share/<코드>` 공유받은 결과. GitHub Pages 하위 경로에서 새로고침해도 동작하도록 해시 주소를 사용합니다.
- 질문 화면: 한 화면에 질문 하나와 공통 여섯 응답을 가로 6칸 게이지로 표시합니다. 왼쪽 끝이 1(전혀 그렇지 않다), 오른쪽 끝이 6(매우 그렇다)이며 게이지 양 끝에 ‘그렇지 않다’·‘그렇다’를 적고, 선택한 칸의 응답 문구를 게이지 아래에 보여 줍니다. 각 칸은 화면 낭독기용 응답 문구를 가진 라디오 버튼이라 방향키로도 고를 수 있습니다. 응답해야 다음 질문으로 넘어가며, 이전 질문으로 돌아가 답을 바꿀 수 있습니다.
- 진행 저장: 답변은 브라우저의 세션 저장소에 두어 새로고침 후 첫 미응답 질문부터 이어 합니다. 저장소를 쓸 수 없어도 검사는 진행됩니다. 알 수 없는 질문 ID와 1~6 밖의 응답은 읽을 때 버립니다.
- 미완료: 모든 질문에 답해야 결과로 이동합니다. 미완료 상태에서 결과 주소로 들어오면 첫 미응답 질문으로 보냅니다.
- 결과 화면은 위에서부터 다음 순서로 구성합니다.
  1. **1~3순위 무기:** 무기 아이콘과 이름을 보여 주며 1순위를 가장 크게 강조합니다. 순위 카드를 누르면 아래 차트와 영상이 그 무기로 바뀝니다(기본 1순위).
  2. **기준 비교:** 다섯 기준을 한방·자유·연계·자원·반격으로 표기한 오각형 방사형 차트에 나의 임시 0~100 값과 선택한 무기의 기준값을 함께 그립니다. 같은 값을 표로도 보여 줍니다.
  3. **무기 소개 영상:** 미리보기 이미지를 누르면 그 자리에서 YouTube 영상을 바로 재생합니다. 개인정보 보호 강화 주소(youtube-nocookie.com)를 사용합니다.
  4. **결과 공유:** ‘이미지로 공유’는 1~3순위와 1순위 기준 비교 차트를 담은 1080×1350 PNG를 만들어 기기 공유 기능으로 보내고, 지원하지 않으면 파일로 저장합니다. ‘링크 공유’는 공유 링크를 기기 공유 기능으로 보내거나 클립보드에 복사합니다.
  5. 답변 수정하기, 처음부터 다시 하기, 작품 선택으로.
- 공유 링크: 답변 대신 결과 자체를 담아 질문 데이터가 바뀌어도 같은 결과를 보여 줍니다. 외부로 보내는 링크는 `<사이트 주소>?r=<작품 ID>.<1순위>.<2순위>.<3순위 weapon_id>.<attack>.<freedom>.<combo>.<resource>.<counter>`이며 축 값은 반올림한 0~100 정수, 미측정은 `-`입니다. 공유 창·메신저·복사 과정에서 `#`·`&`·`=` 같은 문자가 인코딩되거나 잘려 결과가 열리지 않는 문제를 피하려고 `#` 없이 인코딩되지 않는 문자(영문·숫자·`.`·`_`·`-`)만 씁니다. 링크로 들어오면 내부 주소 `#/<작품 ID>/share/<코드>`로 바꿔 새로고침해도 결과가 유지되며, 인코딩된 주소도 해석합니다. 링크 공유에는 문구 없이 주소만 넘겨 주소가 다른 글과 합쳐지지 않게 합니다. 무기 기준값은 링크를 연 시점의 데이터를 사용합니다. 알 수 없는 무기·중복·범위 밖 값이 있으면 검사 화면으로 보냅니다. 공유받은 결과는 ‘친구’ 기준으로 표시하고 답변 수정 대신 ‘나도 검사하기’를 제공합니다.
- 무기 아이콘·영상의 출처와 관리 위치는 [시트 데이터 설계](data-schema.md)의 ‘사이트 표시 자료’를 따릅니다.

## 검증할 내용

- 입문자가 용어 설명 없이도 질문을 이해하는가?
- 선택지의 표현이 한쪽을 더 좋아 보이게 만들지 않는가?
- 각 추천 결과에 답변과 연결된 이유가 있는가?
- 일부 무기가 구조적으로 추천되지 않거나 지나치게 자주 추천되지 않는가?
- 다른 작품의 특징이나 오래된 설명이 와일즈 기준으로 섞이지 않았는가?
- 동점과 답변 수정 시 결과가 일관적인가?
- 양수·음수 가중치와 응답 1~6 조합에서 부호와 기여도 크기가 올바른가?
- 한 질문의 여러 축이 각각 다른 가중치로 반영되며, 0·빈칸 가중치가 영향을 주지 않는가?
- 미완료·미측정 축이 0으로 바뀌거나, 답변 수정이 중복 누적되지 않는가?
- 각 축에 필요한 문항이 있는가? 한 축에 문항이 많다는 이유만으로 다른 축보다 비교 중요도가 높아지지 않는가?

원본 시트에는 무기 14개의 기준값과 질문 후보를 입력했습니다.
무기 수치와 질문·가중치는 참고 자료, 무기 특성, 문항 중복 여부를 검토하며 원본 시트에서 계속 보정합니다.
