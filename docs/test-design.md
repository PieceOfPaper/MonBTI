# 검사 및 무기 추천 설계

- 상태: 선택 기준·6단계 응답·축별 집계 규칙 확정, 실제 문항·무기 추천 계산 설계 대기
- 최신 방향 반영일: 2026-10-05

## 확정된 설계 조건

- 기준 작품을 선택한 다음 검사합니다. 현재는 와일즈만 지원합니다.
- 입문자가 게임 지식 없이 답할 수 있어야 합니다.
- 입문자의 무기 선택에 도움을 주고, 기존 유저에게는 재미를 제공합니다.
- 질문에 답하는 MBTI 검사와 비슷한 경험을 지향합니다.
- 멋짐 등 주관적인 인상보다 손에 익숙해질 수 있는 플레이 특성을 기준으로 합니다.
- 참고 자료의 세부 채택 범위와 무기별 평가는 미정입니다.

## 확정된 무기 선택 기준

| 축 이름 | 영문명·필드 이름 | 짧은 표시 | 평가 내용 |
| --- | --- | --- | --- |
| 공격 성향 | attack | 지속 ↔ 한방 | 꾸준히 대미지를 누적하는 스타일과 준비하거나 모아서 한 번에 넣는 스타일 사이의 성향 |
| 자유도 | freedom | 자유도 | 공격 중 이동·방향 전환과 다른 행동으로의 전환이 자유로운 정도 |
| 콤보 의존 | combo | 콤보 | 연속된 공격을 이어가야 제 역할을 하는 정도 |
| 자원 부담 | resource | 자원 | 자원 확인·보충·유지에 신경 써야 하는 정도 |
| 카운터 의존 | counter | 카운터 | 카운터 중심으로 플레이해야 무기의 장점을 살릴 수 있는 정도 |

공격 성향은 두 스타일 사이의 성향으로 다룹니다. 나머지 네 축은 정도가 높고 낮은 구조로 다룹니다.
무기 기준값과 사용자 성향의 범위는 0~100입니다. 실제 무기별 기준값, 추천 가중치와 무기 비교 공식은 아직 정하지 않았습니다.
축별 영문명, 질문의 `axis`·`reverse`와 데이터 참조 규칙은 [시트 데이터 설계](data-schema.md)를 따릅니다.
축 사이에 관련성이 있더라도 각 축을 따로 평가하며, 한 축의 특성으로 다른 축의 점수를 자동으로 정하지 않습니다.
정도 자체를 무기의 강함이나 사용자의 실력으로 해석하지 않습니다.

### 공격 성향

- 공격 리듬과 타격감, 한 방의 보상과 실패 부담을 이 항목에서 다룹니다.
- 공격 속도나 타격 횟수만으로 지속형과 한방형을 구분하지 않습니다.

### 자유도

- 공격 중 원하는 방향으로 이동하거나 방향을 바꿀 수 있는지를 봅니다.
- 공격을 멈추고 회피·가드 등 다른 행동으로 넘어가기 쉬운지도 포함합니다.
- 단순한 이동 속도와 구분합니다. 행동 제약이 입문자의 적응에 주는 부담을 봅니다.

### 콤보 의존

- 콤보의 존재 여부보다 공격을 이어가지 못했을 때 제 역할을 하기 어려운 정도를 봅니다.
- 콤보가 끊겼을 때의 손실과 다시 시작하는 부담을 포함합니다.
- 조작 적응에 관한 부담은 이 항목에서 다루며, 입력 복잡도를 별도 축으로 두지 않습니다.
- Xbox 패드의 Y·B 버튼 조합을 전제로, 버튼 조합의 복잡함과 순서대로 입력해야 하는지를 별도로 평가하지 않습니다. 특수한 입력 예외도 평가 범위에서 제외합니다.

### 자원 부담

- 자원의 개수나 존재 여부보다 실제로 신경 써야 하는 정도를 봅니다.
- 확인 빈도, 보충·유지에 드는 수고, 부족하거나 유지에 실패했을 때의 부담을 포함합니다.
- 자연스럽게 넘쳐나 별도로 신경 쓸 필요가 없는 자원은 존재한다는 이유만으로 부담을 높이지 않습니다.
- 준비와 자원 관리는 이 항목에 포함합니다.

### 카운터 의존

- 카운터 기술이 있는지가 아니라 카운터 중심의 플레이가 얼마나 필요한지를 봅니다.
- 선택적으로 사용하는 정도라면 낮고, 카운터를 적극적으로 성공시켜야 제 역할을 한다면 높게 평가합니다.
- 카운터 위주가 아닌 경우의 가드·회피 선택은 별도 축으로 나누지 않습니다.

## 별도 평가에서 제외할 요소

- 멋짐과 외형 등 주관적인 인상은 현재 선택 기준에 포함하지 않습니다.
- 패턴 학습과 상황 판단은 모든 무기에 필요한 공통 요소로 보고 별도 축으로 두지 않습니다.
- 방어 방식을 가드·회피·카운터로 분류하는 대신 카운터 의존을 사용합니다.
- 입력 복잡도는 별도 축으로 두지 않으며, 콤보 입력 순서와 특수한 입력 예외도 평가하지 않습니다.
- 조준과 거리 유지 부담은 현재 검사에 포함하지 않습니다.

## 확정된 응답 및 성향 계산

- 모든 질문은 동일한 1~6단계 동의 척도를 사용합니다.
- 질문당 축 하나를 측정하며, 질문 데이터는 `axis`와 `reverse`로 축·방향을 지정합니다.
- 질문은 `question_order` 순서로 모든 사용자에게 동일하게 표시합니다. 답변에 따른 질문 분기는 사용하지 않습니다.
- 3과 4 사이가 중립점이며, 별도의 중립 선택지는 없습니다.
- 기본 응답은 아래 여섯 개입니다. ‘잘 모르겠다’는 별도 제안이며 추가 여부는 미정입니다.

| 응답 | 표시 문구 | 정방향 기준값 | 역방향 기준값 |
| --- | --- | --- | --- |
| 1 | 전혀 그렇지 않다 | 0 | 100 |
| 2 | 그렇지 않다 | 20 | 80 |
| 3 | 조금 그렇지 않다 | 40 | 60 |
| 4 | 조금 그렇다 | 60 | 40 |
| 5 | 그렇다 | 80 | 20 |
| 6 | 매우 그렇다 | 100 | 0 |

### 환산과 집계

1. 응답은 정수 `r ∈ {1, 2, 3, 4, 5, 6}`로 저장합니다. 응답 문구나 화면 위치로 식별하지 않습니다.
2. 정방향 환산값은 `20 × (r - 1)`입니다.
3. `reverse = TRUE`인 문항은 `100 - 정방향 환산값`으로 계산합니다. 동의할수록 해당 축이 낮아집니다.
4. 환산값은 문항의 `axis` 하나에만 반영합니다.
5. 사용자 축 값은 같은 축을 측정한 응답들의 산술평균입니다. 첫 구현에서는 문항 가중치를 두지 않고 동일하게 반영합니다.
6. 계산 중에는 평균을 반올림하지 않습니다. 화면 표시 정밀도는 추후 UI에서 정합니다.
7. 응답이 없는 축은 `null`로 유지합니다. 다른 축에 대한 답변으로 0이나 50을 채우지 않습니다.
8. 답변 수정 시 기존 응답을 교체하고 현재 답변 전체에서 다시 계산합니다. 이전 값을 중복 누적하지 않습니다.

예를 들어 같은 축의 정방향 응답 2와 역방향 응답 2는 각각 20과 80으로 환산되며, 평균은 50입니다.
무응답은 응답 1과 다르며, 미완료 검사에서 값을 임의로 넣지 않습니다.
초기에는 모든 문항 응답을 마친 뒤 결과 단계로 진행하도록 구현합니다.
예시 질문 하나는 공격 성향만 측정하므로 다른 네 축이 아직 채워지지 않습니다.

### 문항 작성 원칙

질문은 여섯 단계로 동의 정도를 답할 수 있는 평서문으로 작성합니다.
한 질문에 서로 다른 취향을 섞지 않으며, 동의할 때 `axis`가 높아지는지 낮아지는지 확인해 `reverse`를 설정합니다.
높은 값과 낮은 값의 의미는 위 다섯 축의 정의를 따릅니다.
부담이 높아도 괜찮다는 수용 정도와 부담이 높은 플레이 자체를 원하는 선호를 같은 의미로 작성하지 않습니다.

## 결정할 사항

| 항목 | 현재 상태 | 검토할 내용 |
| --- | --- | --- |
| 선택 기준 | 다섯 축·초기 입력 범위 0~100 | 실제 무기별 평가는 미정 |
| 데이터 원본 | 시트·열 구조 준비 완료 | Wilds_Weapon, Wilds_Question. JSON 변환·연동 구현 대기 |
| 유형 구조 | 미정 | 유형 코드·이름의 사용 여부, 유형과 무기 사이의 관계 |
| 문항 수 | 미정 | 설명 부담, 소요 시간, 중복 문항 |
| 답변 형식 | 1~6단계 동의 척도 확정 | 공통 여섯 응답, 중립 선택지 없음 |
| 사용자 성향 계산 | 정·역방향 환산 후 축별 산술평균 | 별도 문항 가중치 없음, 미측정 축은 null |
| 잘 모르겠다 | 미정 | 도입 시 환산값 없이 집계에서 제외하는 방식 검토 |
| 추천 계산 | 미정 | 유형별 배정, 무기별 점수, 성향과 무기 특성의 비교 등 |
| 동점 처리 | 미정 | 복수 추천, 추가 질문, 일관된 우선순위 등 |
| 결과 구성 | 미정 | 대표 추천, 추천 이유, 차순위, 취향이 갈릴 부분 |
| 답변 수정·재검사 | 미정 | 이전 답변 수정 시 재계산, 검사 초기화 |
| 결과 공유 | 미정 | 링크, 이미지, 결과 재현에 필요한 데이터 |

위 다섯 축 외에 앞서 제안된 성향 축, 18~24문항, 성향 코드와 무기별 점수 조합은 확정 사항이 아닙니다.

## 기획할 때 사용할 작성 형식

### 무기별 특성

무기 ID, 표시 이름, 기준 작품·업데이트, 다섯 축의 평가와 이유, 플레이 특징, 입문자 설명, 근거 자료 링크, 검토 상태를 기록합니다.
모든 무기를 같은 항목으로 비교하되, 단순히 강한 무기를 선호 성향과 동일시하지 않습니다.

### 질문

질문 ID, 표시 순서, 평서문 본문, 측정 축(`axis`), 역방향 여부(`reverse`)를 원본 시트에 기록합니다.
선택지 문구와 응답별 환산값은 공통 규칙을 사용하며 문항마다 반복 저장하지 않습니다.
실력이나 이미 쓰는 무기를 묻는 것과 플레이 취향을 묻는 것을 구분합니다.
게임 용어가 꼭 필요하면 쉽게 풀어 설명합니다.

### 결과

결과 ID, 무기 또는 유형, 짧은 소개, 추천 이유, 취향이 갈릴 특징, 근거 및 검토 상태를 기록합니다.
수치 표시를 도입하면 계산 방식과 의미를 함께 정합니다.

## 검증할 내용

- 입문자가 용어 설명 없이도 질문을 이해하는가?
- 선택지의 표현이 한쪽을 더 좋아 보이게 만들지 않는가?
- 각 추천 결과에 답변과 연결된 이유가 있는가?
- 일부 무기가 구조적으로 추천되지 않거나 지나치게 자주 추천되지 않는가?
- 다른 작품의 특징이나 오래된 설명이 와일즈 기준으로 섞이지 않았는가?
- 동점과 답변 수정 시 결과가 일관적인가?
- 정방향·역방향에서 응답 1~6이 각각 올바르게 환산되는가?
- 미완료·미측정 축이 0으로 바뀌거나, 답변 수정이 중복 누적되지 않는가?
- 각 축에 필요한 문항이 있는가? 한 축에 문항이 많다는 이유만으로 다른 축보다 비교 중요도가 높아지지 않는가?

원본 시트에 무기 14개의 임시값과 예시 질문 하나를 넣었습니다.
실제 무기 평가와 질문은 참고 자료 및 무기 특성 검토 후 원본 시트에서 작성합니다.
