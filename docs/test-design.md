# 검사 및 무기 추천 설계

- 상태: 선택 기준·6단계 응답·사용자 점수 정규화·추천 계산 확정, 결과 화면·추천 공식 구현
- 최신 방향 반영일: 2026-10-08

## 확정된 설계 조건

- 기준 작품을 선택한 다음 검사합니다. 현재는 와일즈만 지원합니다.
- 입문자가 게임 지식 없이 답할 수 있어야 합니다.
- 입문자의 무기 선택에 도움을 주고, 기존 유저에게는 재미를 제공합니다.
- 질문에 답하는 MBTI 검사와 비슷한 경험을 지향합니다.
- 멋짐 등 주관적인 인상보다 손에 익숙해질 수 있는 플레이 특성을 기준으로 합니다.
- 참고 자료의 세부 채택 범위와 무기별 평가는 미정입니다.

## 확정된 무기 선택 기준

| 축 이름 | 영문명·필드 이름 | 짧은 표기 | 평가 내용 |
| --- | --- | --- | --- |
| 대미지 집중도 | attack | 한방 | 자주 대미지를 누적하는 방식과 준비한 기회에 큰 대미지를 집중하는 방식 사이의 성향 |
| 자유도 | freedom | 자유 | 행동을 시작한 뒤 마음을 바꿨을 때 공격·이동·방향·회피·가드 등 원하는 다음 행동으로 빠르게 전환할 수 있는 정도 |
| 운용 복잡도 | complexity | 복잡 | 제 역할을 위해 상황에 맞는 행동·파생·상태 전환을 골라야 하는 정도 |
| 관리 부담 | management | 관리 | 전투 중 무기 고유 자원·게이지·강화 상태·지속 시간 등을 꾸준히 확인하고 유지·소비·보충해야 하는 정도 |
| 카운터 취향 | counter | 반격 | 몬스터의 행동을 기다렸다 정확한 때에 받아치는 플레이를 선호하는 정도와 무기의 카운터 중심도 |

`attack`은 내부 필드명이며 사용자 화면에는 이해하기 쉬운 **한방**으로 표시합니다. 대미지 집중도와 카운터 취향은 사용자의 선호와 무기 특성이 얼마나 가까운지를 보고, 자유도·운용 복잡도·관리 부담은 무기의 행동 특성과 요구 수준을 평가합니다.
결과 화면·차트·공유 이미지에서는 짧은 표기 **한방·자유·복잡·관리·반격**을 이 순서로 사용합니다. 한방은 값이 높을수록 한방형, 낮을수록 지속형입니다. 결과 화면에는 기준별 설명 문구를 따로 두지 않고, 쉬운 설명은 검사 설명 화면에서만 보여 줍니다.
무기 기준값은 0~100이며 25점 단위로 제한하지 않습니다. 질문 가중치는 -100~100입니다. 사용자 응답의 축별 기여도를 합산한 뒤 축마다 0~100으로 정규화하여 무기 값과 비교합니다. 무기별 기준값은 참고 자료와 현재 추천 공식의 의미를 바탕으로 입력했으며 테스트를 통해 계속 보정할 수 있습니다. 자유도 세부 평가는 아래 가중 합산 규칙을 사용하지만 다른 축도 고정된 단계 없이 필요한 만큼 세분화할 수 있습니다.
축별 영문명, 질문의 다섯 가중치 필드와 데이터 참조 규칙은 [시트 데이터 설계](data-schema.md)를 따릅니다.
축 사이에 관련성이 있더라도 각 축을 따로 평가하며, 한 축의 특성으로 다른 축의 점수를 자동으로 정하지 않습니다.
정도 자체를 무기의 강함이나 사용자의 실력으로 해석하지 않습니다.

### 대미지 집중도

- 낮을수록 짧은 기회를 자주 활용해 대미지를 계속 누적하는 지속형, 높을수록 준비·대기 후 얻은 기회에 큰 대미지를 집중하는 한방형에 가깝습니다.
- 공격 리듬과 타격감, 결과를 기다리는 시간, 한 번 성공했을 때의 보상과 실패했을 때 다시 준비해야 하는 부담을 함께 봅니다.
- 빠른 무기와 느린 무기를 나누는 축이 아닙니다. 공격 속도·모션 길이·타격 횟수 하나만으로 값을 정하지 않습니다.
- 큰 공격이 있어도 평소 운용의 중심이 지속적인 누적이라면 높게 평가하지 않고, 공격이 빨라도 특정 기회에 준비한 대미지가 집중된다면 높을 수 있습니다.

### 자유도

자유도는 단순한 기동성이 아니라 **입문자가 행동을 시작한 뒤 마음을 바꿨을 때, 원하는 다음 행동으로 얼마나 빠르고 자연스럽게 전환할 수 있는가**를 뜻합니다. 공격·회피 버튼이 입력 대기열에 들어갔더라도 현재 모션이 끝난 뒤에야 실행된다면 자유도가 높은 것으로 보지 않습니다.

| 평가 항목 | 비중 | 판단 기준 |
| --- | ---: | --- |
| 위기 전환성 | 35% | 일반적인 공격 뒤 회피나 가드로 얼마나 빨리 전환할 수 있는가. 헛쳤을 때의 회복과 후딜레이도 포함 |
| 공격 즉응성 | 25% | 기본 공격 입력 뒤 실제 공격 판정이 얼마나 빨리 나오는가. 차지를 선택해 기다리는 시간과 강제 선딜레이를 구분 |
| 방향·위치 수정 | 25% | 공격 중이나 공격 사이에 방향을 바꾸고 위치를 조정하거나 대상을 다시 겨눌 수 있는가 |
| 행동 단위 | 15% | 한두 번만 공격하고 멈출 수 있는가, 아니면 긴 동작·연계가 끝날 때까지 다음 선택이 제한되는가 |

각 세부 항목은 먼저 `0·25·50·75·100`으로 평가합니다.

| 세부 점수 | 공통 판정 |
| ---: | --- |
| 0 | 기본 행동 대부분이 길게 고정되고, 공격 시작과 다음 행동 전환이 모두 매우 늦음 |
| 25 | 짧은 선택지는 일부 있지만 입문자가 쓰는 주요 행동은 끝날 때까지 기다려야 하는 경우가 많음 |
| 50 | 짧고 유연한 행동과 제약이 큰 행동이 섞여 있어 기술 선택에 따라 체감이 달라짐 |
| 75 | 기본 운용은 대체로 즉시 전환할 수 있고, 선택적인 큰 기술에서만 제약이 뚜렷함 |
| 100 | 일반적인 운용 대부분에서 공격·방어·이동·방향 수정을 바로 선택할 수 있음 |

원점수는 아래처럼 계산하고 `0~100` 범위에서 가장 가까운 5점 단위로 반올림합니다.

`freedom_raw = 위기 전환성 × 0.35 + 공격 즉응성 × 0.25 + 방향·위치 수정 × 0.25 + 행동 단위 × 0.15`

판정할 때는 다음 경계를 지킵니다.

- 자유도의 목적은 입문자가 느끼는 조작 답답함을 비교하는 것입니다. 단순 이동 속도, 공격 속도, 화력, 생존력은 직접 점수가 아닙니다.
- 회피뿐 아니라 즉시 사용할 수 있는 일반 가드도 위기 전환으로 인정합니다. 카운터의 타이밍·성공 보상·운용 중심도는 `counter`에서 평가하며 자유도에 중복 가산하지 않습니다.
- 최적 화력 콤보보다 입문자가 처음 사용할 안전한 기본 운용을 기준으로 합니다. 선택적인 필살기나 긴 마무리 기술 하나만으로 전체 자유도를 낮추지 않습니다.
- 콤보 파생 수가 많아도 도중에 회피·가드로 빠져나오기 어렵다면 자유도가 높지 않습니다. 파생과 운용 구조를 익히는 부담은 `complexity`에서 따로 평가합니다.
- 모으는 동안 이동하거나 취소 시점을 고를 수 있다면 공격 속도가 느려도 자유도가 높을 수 있습니다.
- 평소 계획에서 샛길로 빠지는 성격이나 잠깐 다른 일을 했다 돌아오는 생활 습관은 자유도와 관계없습니다.

### 운용 복잡도

- 낮을수록 몇 가지 기본 행동이나 상황에 맞지 않는 선택으로도 역할을 수행하기 쉽고, 높을수록 올바른 행동·파생·상태 전환을 골라야 제 성능을 내기 쉽습니다.
- 판단해야 하는 핵심 행동의 수, 상황별 파생 선택, 정해진 운용 구조, 흐름이 끊겼을 때의 손실과 정상 운용으로 돌아가는 부담을 포함합니다.
- 기술·콤보·파생의 개수만으로 값을 높이지 않습니다. 행동 조합이 많아도 대부분의 선택이 유효하고 기본 역할에 기여한다면 낮게 평가할 수 있습니다.
- 해머는 행동 조합과 콤보가 생각보다 다양하지만, 어느 선택을 해도 대체로 공격과 기절 누적에 기여하고 잘못된 파생이 무기 상태 전체를 무너뜨리지 않으므로 복잡도를 낮게 평가합니다.
- 반대로 특정 행동을 선행하거나 현재 상태에 맞는 파생을 골라야 핵심 성능이 나오는 무기는 복잡도를 높게 평가합니다.
- 단순히 행동이 이어지는 과정을 좋아하는 성향, 새로운 활용법을 발견하는 즐거움, 선택지가 많은 자유도를 뜻하지 않습니다.
- Xbox 패드의 Y·B 동시 입력 같은 버튼 조합이나 커맨드를 순서대로 입력하는 난도는 별도 평가하지 않습니다. 특수 입력 예외도 제외합니다.

### 관리 부담

- 낮을수록 공격과 대응 자체에 집중해도 무기 상태가 자연스럽게 유지되고, 높을수록 전투 중 무기 고유 자원·게이지·강화 단계·버프·모드·지속 시간 등을 계속 확인하고 유지·소비·보충해야 합니다.
- 확인해야 하는 상태의 수와 빈도, 여러 상태의 동시 관리, 성능을 유지하기 위한 별도 행동, 필요한 상태를 잃거나 관리에 실패했을 때의 손실을 포함합니다.
- 자원이 존재한다는 이유만으로 높이지 않습니다. 평소 운용만으로 자연스럽게 충당되거나 넘쳐서 별도로 확인하고 개입할 필요가 적다면 관리 부담도 낮게 봅니다.
- 무언가를 모으거나 축적하는 것을 좋아하는 성향, 아껴 두었다가 쓰는 성격, 일상에서 정리·계획을 잘하는지를 직접 평가하지 않습니다. 축적은 실제 전투에서 반복적으로 추적하고 조절해야 할 때만 근거가 됩니다.
- 모든 무기에 공통인 체력·기력 확인, 몬스터 패턴 학습, 일반적인 상황 판단은 포함하지 않습니다. 특정 무기가 이를 고유한 운용 상태로 계속 관리하게 만들 때만 그 추가 부담을 봅니다.
- 퀘스트 전 장비·아이템 준비보다 전투 중 반복되는 관리 부담을 우선합니다. 준비 요소도 전투 운용과 계속 연결될 때만 포함합니다.

### 카운터 취향

- 사용자 점수는 카운터를 감수할 수 있는지가 아니라, 상대의 행동을 기다렸다 정확한 때에 받아쳐 보상을 얻는 플레이를 얼마나 좋아하는지에 가깝습니다.
- 낮은 사용자 값은 카운터 기술 자체를 싫어한다는 뜻이 아닙니다. 먼저 흐름을 만들거나 카운터를 성공시키지 않아도 운용이 이어지는 방식을 더 선호한다는 뜻입니다.
- 무기 값은 카운터 기술의 존재 여부가 아니라 실제 사용 빈도와 운용 정체성에서의 중심도를 봅니다. 선택적인 보조 수단이면 낮고, 적극적인 카운터 성공이 성능·흐름·보상에 중요하면 높습니다.
- 사용자는 카운터의 타이밍·받아치는 쾌감·상대가 만든 기회의 이용·주도권 선호를 서로 다른 질문으로 확인합니다. 카운터가 대체로 매력적인 행동이라는 이유만으로 단순히 “카운터가 재미있는가”만 반복하지 않습니다.
- 추천에서는 사용자 `counter`와 무기 `counter`가 가까울수록 잘 맞는 대칭 취향 축으로 비교합니다. `|사용자 값 - 무기 값|`을 이 축의 기본 불일치로 사용하며, 낮은 쪽 또는 높은 쪽 한 방향에만 추가 벌점을 주지 않습니다.
- 몬스터가 무언가를 할 때 정해진 대응을 정확한 때에 돌려주는 플레이를 다룹니다. 일반적인 패턴 학습과 상황 판단 전체를 카운터 취향으로 계산하지 않습니다.
- 카운터 위주가 아닌 무기가 가드와 회피 중 무엇을 쓰는지는 이 축에서 다시 나누지 않습니다.

## 별도 평가에서 제외할 요소

- 멋짐과 외형 등 주관적인 인상은 현재 선택 기준에 포함하지 않습니다.
- 패턴 학습과 상황 판단은 모든 무기에 필요한 공통 요소로 보고 별도 축으로 두지 않습니다.
- 방어 방식을 가드·회피·카운터로 분류하는 대신 카운터 취향을 사용합니다.
- 입력 커맨드 난도는 별도 축으로 두지 않으며, 버튼 입력 순서와 특수한 입력 예외도 평가하지 않습니다.
- 행동 템포는 대미지 집중도와 다른 축의 조합으로 설명할 수 있다고 보고 별도 축으로 추가하지 않습니다.
- 정밀한 부위·각도·거리 조절은 숙련 단계에서 중요하지만 입문자의 초기 무기 선택 기준에서는 제외합니다. 조준과 거리 유지 부담도 현재 검사에 포함하지 않습니다.

## 확정된 응답 및 성향 계산

- 모든 질문은 동일한 1~6단계 동의 척도를 사용합니다.
- 질문마다 다섯 축의 가중치를 입력하며, 한 질문이 여러 축에 서로 다른 강도·방향으로 영향을 줄 수 있습니다.
- 모든 사용자는 같은 질문을 받지만 표시 순서는 검사를 시작할 때 무작위로 섞습니다. 섞은 순서는 진행 답변과 함께 세션에 저장해 새로고침·답변 수정 중에도 유지하고, ‘처음부터 다시 하기’를 누르면 새로 섞습니다. 답변에 따른 질문 분기는 사용하지 않습니다. `question_order`는 원본 시트의 편집 기준 순서이며 화면 표시 순서를 정하지 않습니다.
- 3과 4 사이가 중립점이며, 별도의 중립 선택지는 없습니다.
- 기본 응답은 아래 여섯 개입니다. ‘잘 모르겠다’는 별도 제안이며 추가 여부는 미정입니다.

| 응답 | 표시 문구 | 응답 계수 |
| --- | --- | --- |
| 1 | 전혀 그렇지 않다 | -1 |
| 2 | 그렇지 않다 | -0.6 |
| 3 | 조금 그렇지 않다 | -0.2 |
| 4 | 조금 그렇다 | +0.2 |
| 5 | 그렇다 | +0.6 |
| 6 | 매우 그렇다 | +1 |

### 환산과 집계

1. 응답은 정수 `r ∈ {1, 2, 3, 4, 5, 6}`로 저장합니다. 응답 문구나 화면 위치로 식별하지 않습니다.
2. 응답 계수는 `c(r) = (2 × r - 7) / 5`입니다.
3. 각 질문의 축별 기여도는 `해당 축의 가중치 × c(r)`입니다. 매우 동의하는 응답 6에서 입력한 가중치가 그대로 반영됩니다.
4. 양수 가중치는 동의 시 양수·비동의 시 음수로, 음수 가중치는 동의 시 음수·비동의 시 양수로 반영됩니다. `reverse` 필드는 두지 않습니다.
5. 가중치 0·빈칸은 해당 축에 영향을 주지 않습니다. 빈칸은 데이터 변환에서 0으로 통일합니다. 한 문항에 최소 하나의 0이 아닌 가중치가 있어야 합니다.
6. 사용자 축별 합산값은 답변한 모든 질문의 해당 축 기여도를 더한 값입니다. 이 원시 합계를 아래 확정 정규화 공식의 입력으로 사용합니다.
7. 해당 축에 0이 아닌 가중치가 있는 답변 문항이 하나도 없으면 `null`입니다. 측정된 기여도들이 상쇄된 합계 0은 유효한 계산값입니다.
8. 계산 중에는 반올림하지 않습니다. 답변 수정 시 기존 응답을 교체하고 현재 답변 전체에서 다시 계산해 중복 누적을 방지합니다.

가중치가 attack 100·freedom 50이면 아래처럼 반영합니다.

| 응답 | attack 기여도 | freedom 기여도 |
| --- | --- | --- |
| 1 | -100 | -50 |
| 2 | -60 | -30 |
| 3 | -20 | -10 |
| 4 | +20 | +10 |
| 5 | +60 | +30 |
| 6 | +100 | +50 |

attack을 -100으로 입력하면 위 attack 기여도의 부호가 모두 반대가 됩니다. 예시 질문의 나머지 축은 가중치 0이므로 측정되지 않습니다.
무응답은 응답 1과 다르며 합산에서 제외합니다. 초기에는 모든 문항 응답을 마친 뒤 결과 단계로 진행하도록 구현합니다.

## 사용자 점수 정규화

축 `a`에 대해 답변한 질문의 가중치를 `w(i,a)`, 응답 계수를 `c(r_i)`라고 합니다.

1. 원시 합계: `raw_a = Σ(w(i,a) × c(r_i))`
2. 최대 절댓값: `max_a = Σ|w(i,a)|`
3. 사용자 점수: `user_a = clamp(50 + 50 × raw_a / max_a, 0, 100)`

`max_a`가 0이면 그 축은 측정하지 않은 것으로 보고 `null`을 유지합니다. 50은 질문의 양쪽 방향이 상쇄된 상태, 0과 100은 현재 문항 구성에서 가능한 양 끝입니다. 축마다 자신의 `max_a`로 나누므로 문항 수나 가중치 총량이 많은 축이 추천에서 자동으로 더 중요해지지 않습니다. 계산 중에는 반올림하지 않고 표시할 때만 반올림합니다.

## 무기 적합도와 추천 순위

사용자 점수 `U_a`와 무기 값 `W_a`의 차이는 축의 성격에 따라 다르게 처리합니다.

| 축 | 불일치 `D_a` | 계산 의미 |
| --- | --- | --- |
| attack | `|U_a - W_a|` | 지속형·한방형 취향이 어느 쪽으로든 다르면 벌점 |
| counter | `|U_a - W_a|` | 선제·비카운터형과 카운터 중심형 사이의 취향 거리를 대칭 비교 |
| freedom | `max(0, U_a - W_a)` | 사용자가 원하는 자유도보다 무기가 부족할 때만 벌점 |
| complexity | `max(0, W_a - U_a)` | 무기가 요구하는 운용 복잡도가 사용자의 수용 범위를 넘을 때만 벌점 |
| management | `max(0, W_a - U_a)` | 무기의 관리 부담이 사용자의 수용 범위를 넘을 때만 벌점 |

축 적합도는 `fit_a = 100 - D_a`입니다. 현재 버전은 다섯 축을 같은 비중으로 사용하며, 측정된 축 집합을 `A`라고 할 때 무기 최종 점수는 `score = Σ fit_a / |A|`입니다. 한 축의 값만으로 무기를 탈락시키는 하드 필터는 두지 않습니다.

점수는 반올림하지 않은 값으로 내림차순 정렬해 1~3순위를 정합니다. 최종 점수가 같으면 가장 큰 단일 축 불일치 `max(D_a)`가 작은 무기를 우선하고, 그래도 같으면 `Wilds_Weapon`의 행 순서를 사용합니다. 이 규칙으로 같은 답변과 데이터는 항상 같은 결과를 냅니다.

`counter`의 낮은 사용자 값은 카운터 혐오가 아니라 비카운터·선제·주도형 플레이 선호입니다. 그래서 단순 카운터 호감 질문의 영향은 낮추고, 정확한 타이밍과 주도권 선택처럼 실제 플레이 방식의 차이를 더 강하게 반영합니다.

모든 무기 값은 0~100 범위에서 필요한 만큼 세분화할 수 있으며 25점 단위로 제한하지 않습니다. 현재 값은 기획자가 타당성을 검토하기 위한 초기 보정치이며 기획자 테스트와 지인 테스트 결과에 따라 계속 조정합니다.

### 문항 작성 원칙

앞으로 질문을 만들거나 수정·검토할 때는 [질문 작성 가이드](question-guide.md)를 먼저 참고합니다.
몬헌 지식 없이 떠올릴 수 있는 일상 상황·행동 선호를 간접적으로 묻고, 문장의 뜻은 바로 이해할 수 있게 작성합니다.
하나의 응답을 여러 축으로 해석할 수 있지만, 서로 다른 답을 하고 싶은 독립된 주장들을 한 질문에 묶지 않습니다.
질문은 여섯 단계로 동의 정도를 답할 수 있는 평서문으로 작성합니다.
하나의 상황이나 플레이 선호가 여러 축과 관련되면 해당 축마다 가중치를 지정합니다. 문구와 각 축의 영향 방향이 명확한지 확인합니다.
동의할 때 축 값이 높아지면 양수, 낮아지면 음수로 입력합니다. 영향이 없으면 0 또는 빈칸으로 둡니다.
높은 값과 낮은 값의 의미는 위 다섯 축의 정의를 따릅니다.
부담이 높아도 괜찮다는 수용 정도와 부담이 높은 플레이 자체를 원하는 선호를 같은 의미로 작성하지 않습니다.

| 항목 | 현재 상태 | 검토할 내용 |

| 선택 기준 | 다섯 축·무기 특성값 0~100 | 현재 수치는 참고 자료 기반이며 최종 보정은 미정 |
| 데이터 원본 | 시트·열 구조·JSON 변환·사이트 연동 완료 | Wilds_Weapon, Wilds_Question |

| 문항 수 | 미정 | 설명 부담, 소요 시간, 중복 문항 |

| 사용자 성향 계산 | 축별 가중 합계를 가중치 절댓값 합으로 정규화 | 0~100, 미측정 축은 null. 계산 중 반올림하지 않음 |
| 잘 모르겠다 | 미정 | 도입 시 환산값 없이 집계에서 제외하는 방식 검토 |
| 추천 계산 | 공식 확정·구현 | 대칭 취향 2축·비대칭 요구 3축의 적합도 동일 가중 평균 |

| 결과 구성 | 1~3순위·차트·영상·공유 구현 | 추천 이유, 취향이 갈릴 부분 등 설명 문구 |
| 답변 수정·재검사 | 기본 동작 구현, 기획 미정 | 이전 질문 이동·결과에서 답변 수정·처음부터 다시 하기를 임시 구현. 수정 시 현재 답변 전체로 재계산 |
| 결과 공유 | 이미지·링크 공유 구현 | 링크 미리보기 이미지 등 추가 여부 |

위 다섯 축 외의 성향 축은 현재 추가하지 않습니다. 행동 템포는 기존 축과의 중복을 고려해 제외하고, 정밀도는 입문자의 초기 무기 선택에 적합하지 않다고 보아 제외합니다. 18~24문항, 성향 코드와 무기별 점수 조합은 확정 사항이 아닙니다.

## 기획할 때 사용할 작성 형식

### 무기별 특성

무기 ID, 표시 이름, 기준 작품·업데이트, 다섯 축의 평가와 이유, 플레이 특징, 입문자 설명, 근거 자료 링크, 검토 상태를 기록합니다.
모든 무기를 같은 항목으로 비교하되, 단순히 강한 무기를 선호 성향과 동일시하지 않습니다.

### 질문

질문 ID, 편집 기준 순서, 평서문 본문과 다섯 축의 부호 있는 가중치(`attack`, `freedom`, `complexity`, `management`, `counter`)를 원본 시트에 기록합니다.
선택지 문구와 응답별 환산값은 공통 규칙을 사용하며 문항마다 반복 저장하지 않습니다.
실력이나 이미 쓰는 무기를 묻는 것과 플레이 취향을 묻는 것을 구분합니다.
일상적인 표현과 다축 해석의 검토 기준은 [질문 작성 가이드](question-guide.md)를 따릅니다.

### 결과

결과 ID, 무기 또는 유형, 짧은 소개, 추천 이유, 취향이 갈릴 특징, 근거 및 검토 상태를 기록합니다.
수치 표시를 도입하면 계산 방식과 의미를 함께 정합니다.

## 결과 계산 구현

- **사용자 점수:** 위 ‘사용자 점수 정규화’를 `computeAxisProfile`(`src/core/scoring.js`)에서 계산합니다. 미측정 축은 null로 두어 차트 꼭짓점에서 빼고 표에는 ‘측정 안 됨’으로 표시합니다.
- **무기 추천:** 위 ‘무기 적합도와 추천 순위’를 `src/core/recommend.js`에서 계산합니다. 같은 답변과 데이터는 새로고침해도 같은 결과가 나오고, 답변을 수정하면 현재 답변 전체로 다시 계산합니다. 미측정 축은 평균에서 제외합니다.

## 현재 구현된 화면

아래는 현재 구현 상태입니다.

- 주소: `#/` 작품 선택, `#/wilds/guide` 검사 설명, `#/wilds` 질문, `#/wilds/result` 결과, `#/wilds/share/<코드>` 공유받은 결과. GitHub Pages 하위 경로에서 새로고침해도 동작하도록 해시 주소를 사용합니다.
- 검사 설명 화면: 작품 선택 카드 아래의 가로 ‘검사 설명’ 버튼으로 들어갑니다. 대상(입문자의 무기 선택, 기존 유저의 재미), 진행 방식(질문 수, 여섯 단계 응답, 무작위 순서, 1~3순위 결과), 다섯 기준의 쉬운 설명과 무기 비교 방식(한방·반격은 가까울수록, 자유는 무기가 부족할 때만, 복잡·관리는 무기 요구량이 넘칠 때만 덜 맞음, 다섯 기준 같은 비중), 평가하지 않는 요소와 무기 값이 계속 보정된다는 안내를 보여 주고 ‘검사 시작하기’·‘작품 선택으로’를 제공합니다. 질문 수와 무기 수는 작품 데이터에서 읽습니다.
- 질문 화면: 한 화면에 질문 하나와 공통 여섯 응답을 가로 6칸 게이지로 표시합니다. 왼쪽 끝이 1(전혀 그렇지 않다), 오른쪽 끝이 6(매우 그렇다)이며 게이지 양 끝에 ‘그렇지 않다’·‘그렇다’를 적고, 선택한 칸의 응답 문구를 게이지 아래에 보여 줍니다. 각 칸은 화면 낭독기용 응답 문구를 가진 라디오 버튼이라 방향키로도 고를 수 있습니다. 응답해야 다음 질문으로 넘어가며, 이전 질문으로 돌아가 답을 바꿀 수 있습니다.
- 진행 저장: 답변과 섞은 질문 순서는 브라우저의 세션 저장소에 두어 새로고침 후 같은 순서의 첫 미응답 질문부터 이어 합니다. 저장한 순서가 현재 질문 집합과 맞지 않으면(질문 추가·삭제 등) 순서를 새로 섞고 기존 답변은 유지합니다. 저장소를 쓸 수 없어도 검사는 진행됩니다. 알 수 없는 질문 ID와 1~6 밖의 응답은 읽을 때 버립니다.
- 미완료: 모든 질문에 답해야 결과로 이동합니다. 미완료 상태에서 결과 주소로 들어오면 첫 미응답 질문으로 보냅니다.
- 결과 화면은 위에서부터 다음 순서로 구성합니다.
  1. **1~3순위 무기:** 무기 아이콘과 이름을 보여 주며 1순위를 가장 크게 강조합니다. 순위 카드를 누르면 아래 차트와 영상이 그 무기로 바뀝니다(기본 1순위).
  2. **기준 비교:** 다섯 기준을 한방·자유·복잡·관리·반격으로 표기한 오각형 방사형 차트에 나의 0~100 사용자 점수와 선택한 무기의 기준값을 함께 그립니다. 같은 값을 표로도 보여 줍니다.
  3. **무기 소개 영상:** 미리보기 이미지를 누르면 그 자리에서 YouTube 영상을 바로 재생합니다. 개인정보 보호 강화 주소(youtube-nocookie.com)를 사용합니다.
  4. **결과 공유:** ‘이미지로 공유’는 1~3순위와 1순위 기준 비교 차트를 담은 1080×1350 PNG를 만들어 기기 공유 기능으로 보내고, 지원하지 않으면 파일로 저장합니다. ‘링크 공유’는 공유 링크를 기기 공유 기능으로 보내거나 클립보드에 복사합니다.
  5. 답변 수정하기, 처음부터 다시 하기, 작품 선택으로.
- 공유 링크: 답변 대신 결과 자체를 담아 질문 데이터가 바뀌어도 같은 결과를 보여 줍니다. 외부로 보내는 링크는 `<사이트 주소>?r=<작품 ID>.<1순위>.<2순위>.<3순위 weapon_id>.<attack>.<freedom>.<complexity>.<management>.<counter>`이며 축 값은 반올림한 0~100 정수, 미측정은 `-`입니다. 공유 코드에는 필드 이름이 아니라 고정된 축 순서만 저장하므로 `combo`를 `complexity`로, `resource`를 `management`로 바꿔도 같은 위치의 축 값으로 읽어 기존 링크와 호환됩니다. 공유 창·메신저·복사 과정에서 `#`·`&`·`=` 같은 문자가 인코딩되거나 잘려 결과가 열리지 않는 문제를 피하려고 `#` 없이 인코딩되지 않는 문자(영문·숫자·`.`·`_`·`-`)만 씁니다. 링크로 들어오면 내부 주소 `#/<작품 ID>/share/<코드>`로 바꿔 새로고침해도 결과가 유지되며, 인코딩된 주소도 해석합니다. 링크 공유에는 문구 없이 주소만 넘겨 주소가 다른 글과 합쳐지지 않게 합니다. 무기 기준값은 링크를 연 시점의 데이터를 사용합니다. 알 수 없는 무기·중복·범위 밖 값이 있으면 검사 화면으로 보냅니다. 공유받은 결과는 ‘친구’ 기준으로 표시하고 답변 수정 대신 ‘나도 검사하기’를 제공합니다.
- 무기 아이콘·영상의 출처와 관리 위치는 [시트 데이터 설계](data-schema.md)의 ‘사이트 표시 자료’를 따릅니다.

## 검증할 내용

- 입문자가 용어 설명 없이도 질문을 이해하는가?
- 선택지의 표현이 한쪽을 더 좋아 보이게 만들지 않는가?
- 각 추천 결과에 답변과 연결된 이유가 있는가?
- 일부 무기가 구조적으로 추천되지 않거나 지나치게 자주 추천되지 않는가?
- 다른 작품의 특징이나 오래된 설명이 와일즈 기준으로 섞이지 않았는가?
- 동점과 답변 수정 시 결과가 일관적인가?
- 양수·음수 가중치와 응답 1~6 조합에서 부호와 기여도 크기가 올바른가?
- 한 질문의 여러 축이 각각 다른 가중치로 반영되며, 0·빈칸 가중치가 영향을 주지 않는가?
- 미완료·미측정 축이 0으로 바뀌거나, 답변 수정이 중복 누적되지 않는가?
- 각 축에 필요한 문항이 있는가? 한 축에 문항이 많다는 이유만으로 다른 축보다 비교 중요도가 높아지지 않는가?

## 테스트와 보정 절차

초기 수치와 문항은 통계적으로 확정된 값이 아니라 테스트를 시작하기 위한 기획 가설입니다. 먼저 기획자가 여러 응답 조합을 직접 테스트해 결과 흐름을 확인하고, 적당하다고 판단한 뒤 주변 지인으로 범위를 넓힙니다.

1. 기획자 테스트: 의도적으로 지속형·한방형, 높은·낮은 자유도, 낮은·높은 운용 복잡도, 낮은·높은 관리 부담, 선제·카운터 취향의 응답을 만들어 상위 추천과 축 점수를 확인합니다.
2. 실제 취향 대조: 본인이 잘 아는 무기와 피하고 싶은 무기가 상위·하위에 놓이는지, 추천 이유가 답변과 연결되는지 확인합니다.
3. 지인 테스트: 입문자와 기존 유저를 구분해 결과의 납득도, 상위 3개 중 사용하고 싶은 무기, 실제로 몇 차례 사용한 뒤의 만족도를 받습니다.
4. 기록: 테스트한 데이터·계산 버전, 응답, 축 점수, 추천 순위, 예상 결과, 만족·불만족 이유를 함께 남깁니다.
5. 조정 순서: 오해되는 질문 문구 → 질문 가중치 → 무기 특성값 → 축별 추천 중요도 → 종합 공식 순으로 바꿉니다. 한 번에 여러 층을 바꾸지 않습니다.
6. 버전 비교: 조정 전후에 같은 답변을 다시 계산해 어떤 결과가 왜 바뀌었는지 확인합니다.

소수의 지인 테스트는 통계적 검증으로 부르지 않고 초기 보정과 문제 발견에 사용합니다. 응답이 충분히 쌓이기 전에는 특정 지인의 주무기에 맞춰 전체 수치를 과도하게 조정하지 않습니다.

원본 시트에는 무기 14개의 기준값과 질문 후보를 입력했습니다.
무기 수치와 질문·가중치는 참고 자료, 무기 특성, 문항 중복 여부를 검토하며 원본 시트에서 계속 보정합니다.
