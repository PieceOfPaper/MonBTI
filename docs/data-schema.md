- 최신 방향 반영일: 2026-10-05

## 무기 기준값과 사용자 성향

무기 기준값은 **0~100의 숫자**입니다. 소수도 입력할 수 있습니다.
사용자 성향도 0~100으로 계산하며, 질문 응답은 이 범위의 숫자를 직접 입력받지 않고 1~6단계를 받습니다.
백분율이나 무기의 성능 점수가 아닌 비교용 기준값입니다.
실제 무기별 평가는 아직 정하지 않았으며, 척도 조정 시 시트·변환 규칙·관련 기획을 함께 바꿉니다.

| 열 이름 | 기준 | 0 | 100 |
| --- | --- | --- | --- |
| attack | 공격 성향 | 지속형 | 한방형 |
| freedom | 자유도 | 행동 자유도가 낮음 | 행동 자유도가 높음 |
| combo | 콤보 의존 | 공격 연계에 대한 의존이 낮음 | 공격 연계에 대한 의존이 높음 |
| resource | 자원 부담 | 관리 부담이 낮음 | 관리 부담이 높음 |
| counter | 카운터 의존 | 카운터 중심 플레이의 필요가 낮음 | 카운터 중심 플레이의 필요가 높음 |

무기 탭에는 각 무기의 특성을 입력합니다.
질문 탭은 측정 축(`axis`)과 역방향 여부(`reverse`)만 입력하며, 응답별 기준값은 공통 환산 규칙으로 계산합니다.
기준값은 무기의 강함이나 최종 추천 점수가 아닙니다.
무기 탭의 다섯 기준값은 모두 필수이며, 미평가 값을 임의로 0으로 바꾸지 않습니다.
사용자 성향에서 미측정 축은 `null`, 실제 계산값 0은 유효한 값입니다.

## Wilds_Weapon

- 1행: 열 이름
- 2행부터: 무기당 한 행
- 최초 입력 범위: `A1:G15` — 헤더와 무기 14개

| 열 이름 | 형식 | 입력 규칙 |
| --- | --- | --- |
| weapon_id | 문자열 | 변하지 않는 고유 키. 예: great_sword, lance |
| weapon_name | 문자열 | 화면에 보여줄 한국어 무기 이름 |
| attack | 숫자 | 0~100, 필수 |
| freedom | 숫자 | 0~100, 필수 |
| combo | 숫자 | 0~100, 필수 |
| resource | 숫자 | 0~100, 필수 |
| counter | 숫자 | 0~100, 필수 |

대검, 태도, 한손검, 쌍검, 해머, 수렵피리, 랜스, 건랜스, 슬래시액스, 차지액스, 조충곤, 라이트보우건, 헤비보우건, 활을 등록했습니다.
모든 기준값은 수정 가능한 임시값 50으로 입력했습니다.
별도의 임시 데이터 구분 필드 없이 이 수치를 직접 수정해 사용합니다.

## Wilds_Question

- 1행: 열 이름
- 2행부터: **질문당 한 행**
- 현재 입력 범위: `A1:E2` — 헤더와 예시 질문 하나
- 모든 질문은 공통 여섯 응답을 사용하므로 선택지 행이나 응답별 점수 열을 두지 않습니다.

| 열 이름 | 형식 | 입력 규칙 |
| --- | --- | --- |
| question_id | 문자열 | 질문 고유 키. 문구를 바꾸거나 행을 옮겨도 유지 |
| question_order | 양의 정수 | 질문 표시 순서. 질문 사이에서 중복되지 않음 |
| question_text | 문자열 | 동의 정도를 답할 수 있는 평서문 |
| axis | 문자열 | attack, freedom, combo, resource, counter 중 하나 |
| reverse | 불리언 | FALSE: 동의할수록 축 값 증가. TRUE: 동의할수록 축 값 감소 |

`axis`는 무기 기준 필드와 같은 영문명을 사용합니다.
`reverse`는 체크박스로 입력하며 체크하면 TRUE, 해제하면 FALSE입니다. 빈칸은 FALSE로 간주하지 않고 입력 오류로 처리합니다.
질문을 추가할 때 새 행에 새 `question_id`와 표시 순서를 입력하고 측정 축·역방향 여부를 지정합니다.

### 예시 질문

| question_id | question_order | question_text | axis | reverse |
| --- | --- | --- | --- | --- |
| wilds_q001 | 1 | 나는 준비하거나 힘을 모아서 한 번에 큰 대미지를 넣는 방식이 좋다. | attack | FALSE |

공통 응답 1은 attack 0, 응답 6은 attack 100으로 환산됩니다.
다른 네 축은 이 문항의 계산에 포함되지 않습니다.
역방향 문항은 같은 여섯 응답을 사용하면서 `100 - 환산값`을 적용합니다.

### 공통 응답

| 응답 | 표시 문구 | 정방향 기준값 | 역방향 기준값 |
| --- | --- | --- | --- |
| 1 | 전혀 그렇지 않다 | 0 | 100 |
| 2 | 그렇지 않다 | 20 | 80 |
| 3 | 조금 그렇지 않다 | 40 | 60 |
| 4 | 조금 그렇다 | 60 | 40 |
| 5 | 그렇다 | 80 | 20 |
| 6 | 매우 그렇다 | 100 | 0 |

환산식과 사용자 성향 집계 규칙은 [검사 설계](test-design.md)의 ‘확정된 응답 및 성향 계산’을 따릅니다.
공통 응답 정의와 환산식은 사이트 코드에서 한 번 관리하며 질문 JSON 안에 여섯 선택지를 반복 저장하지 않습니다.
‘잘 모르겠다’는 기본 여섯 응답에 포함하지 않으며 별도 도입 여부는 미정입니다.

## 사이트에서 참조하는 방법

GitHub Pages 정적 사이트에 맞춰 **시트에서 내보낸 데이터를 검증·변환한 JSON을 배포에 포함하는 방식**을 기본으로 합니다.
방문자의 브라우저가 Google 인증이나 시트의 공개 설정에 의존하지 않도록 합니다.
사이트용 JSON 경로는 다음과 같이 계획하며, 이번 작업에서 변환기나 JSON 파일을 구현하지는 않았습니다.

- `src/data/wilds/weapons.json`: 무기 행을 객체 배열로 변환
- `src/data/wilds/questions.json`: 질문당 한 객체로 변환하고 표시 순서로 정렬

### 변환 규칙

1. 원본 스프레드시트를 XLSX로 내보내고 두 탭을 정확한 이름으로 읽습니다.
2. 1행의 열 이름으로 필드를 매핑합니다. 열 위치가 바뀌어도 열 이름이 같으면 같은 필드로 읽습니다.
3. 완전히 빈 행은 건너뜁니다. 질문의 네 기본 필드(ID·순서·문구·axis)가 모두 비어 있고 reverse가 빈칸 또는 기본 체크박스 값 FALSE뿐인 행도 빈 질문 행으로 건너뜁니다. 그 밖에 필수 정보가 일부만 채워진 행은 오류로 처리합니다.
4. 무기는 `weapon_id`로 식별하고 다섯 기준값을 숫자로 보존합니다.
5. 질문은 `question_id`로 식별하고 `question_order`로 정렬합니다. 질문마다 `axis` 하나와 불리언 `reverse`를 보존합니다.
6. 사용자 응답은 `question_id`와 정수 `response`(1~6)로 저장합니다. 문구나 행 번호로 식별하지 않습니다.
7. 측정하지 않은 사용자 축은 `null`로 유지합니다. 무기 데이터에 필요한 수치를 임의로 채우지 않습니다.
8. 데이터 출처의 스프레드시트 ID, 내보낸 시각, 변환한 시각, 데이터 형식 버전을 생성 데이터의 메타데이터에 기록합니다. 기존 선택지 행 방식과 새 질문 행 방식을 구분해 버전을 갱신합니다.

무기·질문 ID 중복, 질문 표시 순서 중복, 필수값 누락, 잘못된 axis, 불리언이 아닌 reverse는 변환 오류로 처리합니다.
무기 기준값은 0~100의 유한한 숫자, question_order는 양의 정수인지 확인합니다.
JSON에는 질문별 선택지·분기 대상·응답별 점수표를 만들지 않습니다.
사이트에서는 응답 1~6 정수 외의 값과 존재하지 않는 질문 ID를 거부합니다.
완료 검사에 필요한 축별 문항이 있는지도 검토합니다. 현재 예시 문항 하나는 공격 성향만 측정합니다.

### 데이터 변경의 반영 순서

1. 원본 시트에서 수치·문항을 수정합니다.
2. 새 XLSX를 내보내고 변환기로 JSON을 생성합니다.
3. 검증 결과와 생성 데이터의 변경 내용을 확인합니다.
4. 생성 JSON을 저장소에 커밋하고 푸시합니다.
5. GitHub Actions의 검증·Pages 배포 후 사이트에서 확인합니다.

원본 시트 수정만으로 이미 배포된 사이트가 즉시 바뀌지는 않습니다.
시트의 공유 권한이나 공개 설정은 이번 작업에서 변경하지 않았습니다.
XLSX 읽기·검증·JSON 변환과 사이트 데이터 로딩은 후속 구현 대상입니다.
수치와 질문은 이 표에서 계속 수정하며, 임시 여부에 따른 별도의 읽기·계산 분기를 두지 않습니다.

## 아직 정하지 않은 계산

응답의 정·역방향 환산과 축별 산술평균은 정했습니다.
무기와의 비교 공식, 축별 추천 가중치, 부담의 선호·허용 범위 처리, 동점 처리와 최종 추천 구조는 미정입니다.
미측정 축은 추천 비교의 근거로 사용하지 않으며 자동으로 0이나 50을 부여하지 않습니다.
‘잘 모르겠다’ 같은 추가 응답을 구현하려면 별도 기획 변경으로 정의해야 합니다.
