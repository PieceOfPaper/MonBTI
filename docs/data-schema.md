## 무기 특성값과 질문 가중치

무기 기준값은 **0~100의 숫자**입니다. 소수도 입력할 수 있습니다.
질문 가중치는 **-100~100의 숫자**이며 소수도 입력할 수 있습니다. 사용자 응답은 1~6단계를 받고, 질문 가중치에 부호 있는 응답 계수를 곱해 축별로 합산합니다. 합산값은 해당 축의 가중치 절댓값 합으로 나누어 0~100 사용자 점수로 정규화합니다.
백분율이나 무기의 성능 점수가 아닌 비교용 기준값입니다.
무기별 수치는 참고 자료를 바탕으로 원본 시트에 입력했으며 아직 보정할 수 있습니다. 척도의 의미를 조정할 때는 시트·변환 규칙·관련 기획을 함께 바꿉니다.

| 열 이름 | 기준 | 0 | 100 |
| --- | --- | --- | --- |
| attack | 공격 성향 | 자주 대미지를 누적하는 지속형 | 준비한 기회에 대미지를 집중하는 한방형 |
| freedom | 자유도 | 행동 중 조정·전환의 제약이 큼 | 이동·방향 전환·취소와 다른 대응 전환이 자유로움 |
| combo | 콤보 의존 | 기본 동작만으로 역할 수행이 쉬움 | 여러 동작·파생·운용 조건의 숙련이 제 성능에 중요함 |
| resource | 자원 부담 | 별도 확인·유지·보충 부담이 낮음 | 전투 중 여러 상태를 계속 관리해야 함 |
| counter | 카운터 취향·중심도 | 카운터가 운용의 중심이 아님 | 카운터 성공이 무기 운용의 핵심 정체성임 |

무기 탭에는 각 무기의 특성을 입력합니다.
질문 탭도 같은 다섯 필드를 사용하되, 값은 무기 특성값이 아니라 해당 문항의 영향 방향·강도를 나타내는 가중치입니다. 양수·음수는 방향, 절댓값은 영향 크기, 0·빈칸은 영향 없음을 뜻합니다. `axis`·`reverse`는 사용하지 않습니다.
기준값은 무기의 강함이나 최종 추천 점수가 아닙니다.
`counter`는 질문 데이터에서는 사용자의 카운터 플레이 선호 방향, 무기 데이터에서는 카운터가 핵심 운용에서 차지하는 중심도를 나타냅니다. 추천 시 두 값은 대칭적으로 비교하며 낮은 사용자 값을 카운터 혐오로 해석하지 않습니다.
무기 탭의 다섯 기준값은 모두 필수이며, 미평가 값을 임의로 0으로 바꾸지 않습니다.
사용자 성향에서 미측정 축은 `null`, 실제 계산값 0은 유효한 값입니다.

## Wilds_Weapon

- 1행: 열 이름
- 2행부터: 무기당 한 행
- 현재 입력 범위: `A1:H15` — 헤더와 무기 14개

| 열 이름 | 형식 | 입력 규칙 |
| --- | --- | --- |
| weapon_id | 문자열 | 변하지 않는 고유 키. 예: great_sword, lance |
| weapon_name | 문자열 | 화면에 보여줄 한국어 무기 이름 |
| attack | 숫자 | 0~100, 필수 |
| freedom | 숫자 | 0~100, 필수 |
| combo | 숫자 | 0~100, 필수 |
| resource | 숫자 | 0~100, 필수 |
| counter | 숫자 | 0~100, 필수 |
| reason | 문자열 | 수치 판단 근거를 적는 편집 메모. 계산·JSON에서 제외 |

대검, 태도, 한손검, 쌍검, 해머, 수렵피리, 랜스, 건랜스, 슬래시액스, 차지액스, 조충곤, 라이트보우건, 헤비보우건, 활을 등록했습니다.
각 기준값은 참고 자료와 무기 특성을 바탕으로 입력했으며 검토에 따라 직접 수정합니다.
`reason`은 입력 근거를 사람이 확인하기 위한 열이고 사이트 데이터로 사용하지 않습니다. 별도의 임시 데이터 구분 필드는 두지 않습니다.

## Wilds_Question

- 1행: 열 이름
- 2행부터: **질문당 한 행**
- 현재 원본 입력 범위: `A1:J26` — 헤더와 질문 25개
- 모든 질문은 공통 여섯 응답을 사용하므로 선택지 행이나 응답별 점수 열을 두지 않습니다.

| 열 이름 | 형식 | 입력 규칙 |
| --- | --- | --- |
| question_id | 문자열 | 질문 고유 키. 문구를 바꾸거나 행을 옮겨도 유지 |
| question_order | 양의 정수 | 질문 표시 순서. 질문 사이에서 중복되지 않음 |
| question_text | 문자열 | 동의 정도를 답할 수 있는 평서문 |
| attack | 숫자 | -100~100. 0·빈칸은 영향 없음 |
| freedom | 숫자 | -100~100. 0·빈칸은 영향 없음 |
| combo | 숫자 | -100~100. 0·빈칸은 영향 없음 |
| resource | 숫자 | -100~100. 0·빈칸은 영향 없음 |
| counter | 숫자 | -100~100. 0·빈칸은 영향 없음 |
| 분류1 | 문자열 | 유사 문항 중복을 확인하기 위한 주된 의미 태그. 계산·JSON에서 제외 |
| 분류2 | 문자열 | 두 번째 의미 태그가 있을 때만 입력. 계산·JSON에서 제외 |

한 질문에서 여러 축에 가중치를 줄 수 있습니다. 최소 하나의 축은 0이 아닌 가중치를 가져야 합니다.
양수는 동의할수록 해당 축이 높아지고, 음수는 동의할수록 낮아집니다. 비동의 응답에서는 부호가 반대로 적용됩니다.
시트의 다섯 가중치 열에는 -100~100 숫자 입력 검증을 적용했습니다.
질문을 추가할 때 새 행에 고유 ID·표시 순서·본문과 각 축의 가중치를 입력합니다.
`분류1`·`분류2`는 질문 기획을 위한 편집 메모입니다. 같은 분류의 질문이 과도하게 늘어나지 않는지 확인할 때 사용하며 변환기의 필수 열이나 사이트 데이터가 아닙니다.

### 계산 예시

아래는 다축 계산 방식을 설명하기 위한 가상 값입니다. 원본 시트의 현재 질문을 뜻하지 않습니다.

| question_id | question_order | question_text | attack | freedom | combo | resource | counter |
| --- | --- | --- | --- | --- | --- | --- | --- |
| example | 1 | 예시 문장 | 100 | 50 | 0 | 0 | 0 |

응답 6은 attack +100·freedom +50, 응답 1은 attack -100·freedom -50으로 반영됩니다. 다른 세 축은 이 문항의 계산에 포함되지 않습니다.
가중치를 -100·-50으로 입력하면 각각의 부호가 반대가 됩니다.

### 공통 응답

| 응답 | 표시 문구 | 응답 계수 |
| --- | --- | --- |
| 1 | 전혀 그렇지 않다 | -1 |
| 2 | 그렇지 않다 | -0.6 |
| 3 | 조금 그렇지 않다 | -0.2 |
| 4 | 조금 그렇다 | +0.2 |
| 5 | 그렇다 | +0.6 |
| 6 | 매우 그렇다 | +1 |

축별 기여도는 `가중치 × (2 × 응답 - 7) / 5`입니다. 답변 문항의 기여도를 축별로 더합니다.
환산식과 집계 규칙은 [검사 설계](test-design.md)의 ‘확정된 응답 및 성향 계산’을 따릅니다.
공통 응답 정의와 환산식은 사이트 코드에서 한 번 관리하며 질문 JSON 안에 여섯 선택지를 반복 저장하지 않습니다.
‘잘 모르겠다’는 기본 여섯 응답에 포함하지 않으며 별도 도입 여부는 미정입니다.

## 사이트에서 참조하는 방법

GitHub Pages 정적 사이트에 맞춰 **시트에서 내보낸 데이터를 검증·변환한 JSON을 배포에 포함하는 방식**을 기본으로 합니다.
방문자의 브라우저가 Google 인증이나 시트의 공개 설정에 의존하지 않도록 합니다.
변환기는 `scripts/convert-sheet.js`, 검증 규칙은 `scripts/sheet-converter.js`에 있습니다. 사이트용 JSON 경로는 다음과 같습니다.

- `src/data/wilds/weapons.json`: 무기 행을 객체 배열로 변환
- `src/data/wilds/questions.json`: 질문당 한 객체로 변환하고 표시 순서로 정렬

### 변환 규칙

1. 원본 스프레드시트를 XLSX로 내보내고 두 탭을 정확한 이름으로 읽습니다.
2. 1행의 열 이름으로 필드를 매핑합니다. 열 위치가 바뀌어도 열 이름이 같으면 같은 필드로 읽습니다.
3. 완전히 빈 행은 건너뜁니다. 질문의 ID·순서·문구가 모두 비어 있고 가중치가 빈칸 또는 0뿐인 행도 건너뜁니다. 기본 필드가 일부만 채워졌거나 기본 필드 없이 0이 아닌 가중치만 있는 행은 오류로 처리합니다.
4. 무기는 `weapon_id`로 식별하고 다섯 기준값을 숫자로 보존합니다.
5. 질문은 `question_id`로 식별하고 `question_order`로 정렬합니다. 다섯 가중치를 부호·크기 그대로 숫자로 보존하며 가중치의 빈칸은 0으로 통일합니다.
6. 사용자 응답은 `question_id`와 정수 `response`(1~6)로 저장합니다. 문구나 행 번호로 식별하지 않습니다.
7. 측정하지 않은 사용자 축은 `null`로 유지합니다. 무기 데이터에 필요한 수치를 임의로 채우지 않습니다.
8. 무기 탭의 `reason`, 질문 탭의 `분류1`·`분류2`는 편집 메모로만 사용하며 사이트용 JSON과 변경 판단에서 제외합니다.
9. 데이터 출처의 스프레드시트 ID, 내보낸 시각, 변환한 시각, 데이터 형식 버전을 생성 데이터의 메타데이터에 기록합니다. 기존 선택지 행·단일 축 구조와 다축 가중치 구조를 구분해 버전을 갱신합니다.

무기·질문 ID 중복, 질문 표시 순서 중복, 필수값 누락, 잘못된 가중치는 변환 오류로 처리합니다.
무기 기준값은 0~100, 질문 가중치는 -100~100의 유한한 숫자인지 확인합니다. 불리언은 숫자로 받지 않습니다. question_order는 양의 정수여야 합니다.
각 질문에는 최소 하나의 0이 아닌 가중치가 필요합니다. 필수 질문 열 여덟 개가 모두 존재하고 중복되지 않는지 검증하며 이전 axis·reverse 구조를 새 구조로 잘못 읽지 않습니다. `분류1`·`분류2` 같은 추가 메모 열은 허용하되 JSON에 포함하지 않습니다.
JSON에는 질문별 선택지·분기 대상·응답별 점수표를 만들지 않습니다.
사이트에서는 응답 1~6 정수 외의 값과 존재하지 않는 질문 ID를 거부합니다.
완료 검사에 필요한 축별 문항이 있는지도 검토합니다. 원본 시트의 질문 수와 배포 JSON의 질문 수는 데이터 갱신 워크플로 실행 전에는 다를 수 있습니다.

### 실행

```sh
npm run data:convert                     # 원본 시트를 XLSX로 내려받아 변환
npm run data:convert -- --input 파일.xlsx  # 직접 내보낸 XLSX를 변환
npm run data:convert -- --if-changed       # 실질 데이터가 바뀐 파일만 갱신
```

내려받기는 시트의 현재 공유 설정에서 XLSX 내보내기 주소에 접근할 수 있을 때만 동작합니다. 실패하면 시트에서 XLSX를 직접 내보내 `--input`으로 지정합니다.
모든 작품의 두 탭을 먼저 검증하고, 오류가 하나라도 있으면 행 번호와 함께 출력한 뒤 JSON을 쓰지 않습니다.
`--input`을 사용할 때 내보낸 시각은 파일의 수정 시각으로 기록합니다.
`--if-changed`는 `exported_at`·`converted_at` 두 시각만 비교에서 제외합니다. 데이터·원본 ID·탭·형식 버전이 같으면 기존 파일과 기록 시각을 보존하고, 달라졌으면 새 데이터와 시각을 기록합니다. 다운로드는 60초 안에 완료되지 않으면 중단합니다.

### 생성 JSON 형식

두 파일은 `meta`와 데이터 배열(`weapons` 또는 `questions`)을 가진 객체입니다.

```json
{
  "meta": {
    "format_version": 3,
    "source": { "spreadsheet_id": "124oQusXZQ6_F9-UYUVAzG3TD7u50oBjKdBIEbrT7Ras", "sheet": "Wilds_Question" },
    "exported_at": "2026-10-05T12:34:47.428Z",
    "converted_at": "2026-10-05T12:34:47.496Z"
  },
  "questions": []
}
```

`format_version`은 선택지 행 구조를 1, 단일 축 구조를 2, 현재 다축 가중치 구조를 3으로 구분합니다.

질문 배열의 각 항목은 다음처럼 질문당 한 객체입니다.

```json
{
  "question_id": "example",
  "question_order": 1,
  "question_text": "예시 문장",
  "attack": 100,
  "freedom": 50,
  "combo": 0,
  "resource": 0,
  "counter": 0
}
```

이 객체의 가중치에는 응답 전 값만 저장합니다. 응답 계수를 곱한 기여도는 실행 시 계산합니다.

### 데이터 변경의 반영 순서

버튼으로 반영할 때:

1. 원본 시트에서 수치·문항을 수정합니다.
2. [Actions → 시트 데이터 갱신](https://github.com/PieceOfPaper/MonBTI/actions/workflows/refresh-data.yml)에서 **Run workflow**를 누르고 `main`으로 실행합니다.
3. 자동 다운로드·검증·변환·테스트·빌드가 성공하면 `weapons.json`·`questions.json` 변경만 커밋합니다. 변경이 없으면 커밋을 생략합니다.
4. 같은 워크플로에서 빌드 산출물을 Pages에 배포합니다. 실행 성공 후 사이트를 확인합니다.

로컬에서 반영할 때:

1. 원본 시트에서 수치·문항을 수정합니다.
2. `npm run data:convert`로 XLSX를 내려받거나 내보낸 파일을 지정해 JSON을 생성합니다.
3. 검증 결과와 생성 데이터의 변경 내용을 확인합니다.
4. 생성 JSON을 저장소에 커밋하고 푸시합니다.
5. GitHub Actions의 검증·Pages 배포 후 사이트에서 확인합니다.

원본 시트 수정만으로 이미 배포된 사이트가 즉시 바뀌지는 않습니다.
시트의 공유 권한이나 공개 설정은 이번 작업에서 변경하지 않았습니다.
수치와 질문은 이 표에서 계속 수정하며, 임시 여부에 따른 별도의 읽기·계산 분기를 두지 않습니다.

## 추천 계산에서의 사용

축 `a`의 질문 가중치를 `w`, 응답 계수를 `c`라고 할 때 사용자 점수는 다음과 같습니다.

- 축별 합계: `raw_a = Σ(w × c)`
- 가능한 절댓값 합: `max_a = Σ|w|`
- 사용자 점수: `user_a = clamp(50 + 50 × raw_a / max_a, 0, 100)`
- `max_a`가 0이면 그 축은 `null`이며 추천 평균에서도 제외합니다.

무기 값은 같은 0~100 척도에서 비교합니다. `attack`·`counter`는 `|user - weapon|`, `freedom`은 `max(0, user - weapon)`, `combo`·`resource`는 `max(0, weapon - user)`를 불일치로 사용합니다. 축 적합도는 `100 - 불일치`이며 측정된 축의 동일 가중 평균이 무기별 최종 추천 점수입니다.

질문의 영향 가중치와 최종 추천에서 축의 중요도는 별개입니다. 질문 수나 가중치 절댓값 합은 정규화 분모에도 함께 반영되므로 특정 축의 최종 비중을 자동으로 높이지 않습니다. 현재 추천 축 가중치는 모두 1입니다.
사용자 점수는 `computeAxisProfile`(`src/core/scoring.js`), 무기 적합도와 순위는 `src/core/recommend.js`에서 계산합니다.

## 사이트 표시 자료

무기 아이콘과 소개 영상은 계산에 쓰지 않는 사이트 표시 자료이므로 원본 시트가 아닌 저장소에서 관리합니다.

- 아이콘: `src/assets/weapons/<작품 ID>/<weapon_id>.webp`. 와일즈는 나무위키 ‘분류:몬스터 헌터 시리즈/무기’의 무기 아이콘을 내려받아 사용합니다.
- 영상: `src/games/<작품 ID>/media.js`의 `weapon_id` → YouTube 영상 ID 표. 와일즈는 캡콤아시아의 ‘몬스터헌터 와일즈 무기/액션 소개 시리즈’ 재생목록에서 무기별 소개 영상을 골랐습니다.
- 시트에 무기를 추가하면 같은 `weapon_id`로 아이콘 파일과 영상 ID를 추가합니다. 없으면 아이콘 대신 무기 이름 첫 글자를 보여 주고 영상 영역을 생략합니다.
‘잘 모르겠다’ 같은 추가 응답을 구현하려면 별도 기획 변경으로 정의해야 합니다.
