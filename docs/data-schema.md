## 공통 기준값

초기 입력 규격은 **0~100의 숫자**입니다. 소수도 입력할 수 있습니다.
백분율이나 무기의 성능 점수가 아닌 비교용 기준값입니다.
실제 무기별 평가는 아직 정하지 않았으며, 척도 조정 시 시트·변환 규칙·관련 기획을 함께 바꿉니다.

| 열 이름 | 기준 | 0 | 100 |
| --- | --- | --- | --- |
| attack | 공격 성향 | 지속형 | 한방형 |
| freedom | 자유도 | 행동 자유도가 낮음 | 행동 자유도가 높음 |
| combo | 콤보 의존 | 공격 연계에 대한 의존이 낮음 | 공격 연계에 대한 의존이 높음 |
| resource | 자원 부담 | 관리 부담이 낮음 | 관리 부담이 높음 |
| counter | 카운터 의존 | 카운터 중심 플레이의 필요가 낮음 | 카운터 중심 플레이의 필요가 높음 |

무기 탭에서는 무기의 특성을, 질문 탭에서는 해당 선택지가 나타내는 선호·수용 정도를 기록합니다.
예를 들어 자유도 100은 무기에서는 높은 행동 자유도를, 선택지에서는 높은 행동 자유도를 선호하는 답변을 뜻합니다.
질문의 수치는 기준값이며, 현재 단계에서 누적 가산점이나 최종 추천 점수로 정의하지 않습니다.

**빈칸과 0은 다릅니다.** 질문에서 빈칸은 해당 축을 측정하지 않는다는 뜻이며 JSON에서는 `null`로 변환합니다.
0은 해당 축의 낮은 쪽 또는 지속형을 명시적으로 선택한 유효한 숫자입니다.
무기 탭의 다섯 기준값은 모두 채워야 하며, 미평가 값을 임의로 0으로 바꾸지 않습니다.

## Wilds_Weapon

- 1행: 열 이름
- 2행부터: 무기당 한 행
- 최초 입력 범위: `A1:G15` — 헤더와 무기 14개

| 열 이름 | 형식 | 입력 규칙 |
| --- | --- | --- |
| weapon_id | 문자열 | 변하지 않는 고유 키. 예: great_sword, lance |
| weapon_name | 문자열 | 화면에 보여줄 한국어 무기 이름 |
| attack | 숫자 | 0~100, 필수 |
| freedom | 숫자 | 0~100, 필수 |
| combo | 숫자 | 0~100, 필수 |
| resource | 숫자 | 0~100, 필수 |
| counter | 숫자 | 0~100, 필수 |

대검, 태도, 한손검, 쌍검, 해머, 수렵피리, 랜스, 건랜스, 슬래시액스, 차지액스, 조충곤, 라이트보우건, 헤비보우건, 활을 등록했습니다.
모든 기준값은 수정 가능한 임시값 50으로 입력했습니다.
별도의 임시 데이터 구분 필드 없이 이 수치를 직접 수정해 사용합니다.

## Wilds_Question

- 1행: 열 이름
- 2행부터: **선택지당 한 행**
- 최초 입력 범위: `A1:K3` — 헤더와 질문 하나의 선택지 두 개
- 같은 `question_id`를 가진 행을 묶어 질문 하나로 읽습니다.

| 열 이름 | 형식 | 입력 규칙 |
| --- | --- | --- |
| question_id | 문자열 | 질문 고유 키. 같은 질문의 선택지 행에서는 반복 |
| question_order | 양의 정수 | 질문 표시 순서. 같은 질문의 모든 행에 동일하게 입력 |
| question_text | 문자열 | 질문 본문. 같은 질문의 모든 행에 동일하게 입력 |
| option_id | 문자열 | 질문 안에서 고유한 선택지 키. 예: A, B |
| option_order | 양의 정수 | 질문 안의 선택지 표시 순서 |
| option_text | 문자열 | 선택지 문구 |
| attack | 숫자 또는 빈칸 | 0~100. 측정하지 않으면 빈칸 |
| freedom | 숫자 또는 빈칸 | 0~100. 측정하지 않으면 빈칸 |
| combo | 숫자 또는 빈칸 | 0~100. 측정하지 않으면 빈칸 |
| resource | 숫자 또는 빈칸 | 0~100. 측정하지 않으면 빈칸 |
| counter | 숫자 또는 빈칸 | 0~100. 측정하지 않으면 빈칸 |

### 예시 질문

- 질문 ID: `wilds_q001`
- 질문: 공격할 때 어떤 방식이 더 마음에 드나요?
- 선택지 A: 꾸준히 공격해서 조금씩 대미지를 쌓고 싶다. — `attack = 0`
- 선택지 B: 준비하거나 힘을 모아서 한 번에 큰 대미지를 넣고 싶다. — `attack = 100`
- 나머지 네 축은 두 선택지 모두 빈칸입니다.

예시를 위해 선택지 두 개를 넣었으며, 모든 질문을 양자택일로 확정한 것은 아닙니다.
새 질문은 새 `question_id`로 추가하고, 선택지는 같은 질문 ID를 사용해 행을 늘립니다.
같은 질문에서 측정하는 축은 모든 선택지에 숫자를 입력하며, 측정하지 않는 축은 모든 선택지에서 비워 둡니다.

## 사이트에서 참조하는 방법

GitHub Pages 정적 사이트에 맞춰 **시트에서 내보낸 데이터를 검증·변환한 JSON을 배포에 포함하는 방식**을 기본으로 합니다.
방문자의 브라우저가 Google 인증이나 시트의 공개 설정에 의존하지 않도록 합니다.
사이트용 JSON 경로는 다음과 같이 계획하며, 이번 작업에서 변환기나 JSON 파일을 구현하지는 않았습니다.

- `src/data/wilds/weapons.json`: 무기 행을 객체 배열로 변환
- `src/data/wilds/questions.json`: 질문 ID로 묶고 선택지를 포함한 객체 배열로 변환

### 변환 규칙

1. 원본 스프레드시트를 XLSX로 내보내고 두 탭을 정확한 이름으로 읽습니다.
2. 1행의 열 이름으로 필드를 매핑합니다. 열 위치가 바뀌어도 열 이름이 같으면 같은 필드로 읽습니다.
3. 완전히 빈 행은 건너뜁니다. 필수 정보가 일부만 채워진 행은 오류로 처리합니다.
4. 무기는 `weapon_id`로 식별합니다. 무기 이름이나 행 번호로 식별하지 않습니다.
5. 질문은 `question_id`로 묶고 `question_order`로 정렬합니다. 선택지는 `option_order`로 정렬합니다.
6. 질문 응답은 `question_id + option_id`로 식별합니다. 문구 변경과 행 이동으로 응답 식별이 바뀌지 않아야 합니다.
7. 기준값은 숫자로, 질문의 빈 기준값은 `null`로 보존합니다.
8. 데이터 출처의 스프레드시트 ID, 내보낸 시각, 변환한 시각, 데이터 형식 버전을 생성 데이터의 메타데이터에 기록합니다.

무기 ID 중복, 질문 안의 선택지 ID·순서 중복, 서로 다른 질문의 표시 순서 중복은 변환 오류로 처리합니다.
같은 질문의 본문·표시 순서가 서로 다른 행도 오류로 처리합니다.
기준값의 범위·숫자 형식, 질문당 선택지 두 개 이상, 하나 이상의 측정 축, 선택지 사이 측정 축의 일치를 확인합니다.
누락한 기준값을 0으로 채우거나 잘못된 행을 조용히 제외하지 않습니다.

### 데이터 변경의 반영 순서

1. 원본 시트에서 수치·문항을 수정합니다.
2. 새 XLSX를 내보내고 변환기로 JSON을 생성합니다.
3. 검증 결과와 생성 데이터의 변경 내용을 확인합니다.
4. 생성 JSON을 저장소에 커밋하고 푸시합니다.
5. GitHub Actions의 검증·Pages 배포 후 사이트에서 확인합니다.

원본 시트 수정만으로 이미 배포된 사이트가 즉시 바뀌지는 않습니다.
시트의 공유 권한이나 공개 설정은 이번 작업에서 변경하지 않았습니다.
XLSX 읽기·검증·JSON 변환과 사이트 데이터 로딩은 후속 구현 대상입니다.
수치와 질문은 이 표에서 계속 수정하며, 임시 여부에 따른 별도의 읽기·계산 분기를 두지 않습니다.

## 아직 정하지 않은 계산

선택지의 기준값을 사용자 성향으로 모으는 방법, 축별 가중치, 무기와의 비교 공식, 동점 처리와 최종 추천 구조는 미정입니다.
질문에서 측정하지 않은 축은 계산 근거로 사용하지 않으며, 미측정 축에 자동으로 0이나 50을 부여하지 않습니다.
입력 규격을 마련한 것과 추천 계산 방식을 확정한 것을 구분합니다.
